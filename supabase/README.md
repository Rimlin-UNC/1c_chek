# Supabase: отдельный демонстрационный контур

Проект: `chek.base` (`putddctwdskfdzichigx`, PostgreSQL 17).

Контур `chek_demo` содержит **только синтетические данные**: 2 компании,
3 участника, 12 чеков и 24 позиции. Он не заменяет рабочие таблицы приложения,
не хранит реальные ФН/ФД/ФП, контакты, пароли или согласия. Рабочая `DATABASE_URL`
приложения не меняется.

## Доступ

- Базовые таблицы `chek_demo.*`: RLS включён и принудителен; `anon` и
  `authenticated` не имеют доступа к схеме и таблицам.
- Чтение для UI: только представления `public.chek_demo_*` и RPC
  `public.chek_demo_snapshot()`, возвращающие синтетический read-only снимок.
- Запись из браузера не предусмотрена. Сервисный ключ в браузер не передаётся.
- В Supabase Auth отключена свободная регистрация (`disable_signup=true`).
  Приложение использует собственную авторизацию; Supabase Auth пока не подключён.

## Миграции

Файлы `supabase/migrations` названы версиями, под которыми миграции применены к
проекту (`supabase_migrations.schema_migrations`), и побайтно совпадают с
применённым SQL (сверено по md5, вычисленному на стороне PostgreSQL, 02.11.2026):

| Версия | Что делает |
|---|---|
| `20261101154331_chek_demo_readonly_contour` | схема `chek_demo`, RLS, представления `public.chek_demo_*`, RPC `chek_demo_snapshot()`, синтетический набор |
| `20261101155225_chek_demo_fix_item_seed` | пересоздаёт 24 позиции чеков с детерминированными id |
| `20261101164303_chek_demo_revoke_view_write_default_grants` | оставляет `anon`/`authenticated` только чтение представлений |

Каждый файл применяется **один раз**, по порядку. Ошибочный повторный запуск
безопасен: файл либо проходит снова, либо откатывается целиком (так,
`20261101154331` после `20261101155225` откатывается из-за
`unique (receipt_id, position)`), и контур не меняется.

## Проверка

`supabase/verify.sql` — один SELECT только для чтения; ожидание записано в
последней строке файла. Он проверяется дважды:

- в CI на чистом PostgreSQL 17 (`tests/test_supabase_migrations.py`):
  миграции по порядку → `verify.sql`, затем повторный запуск каждого файла →
  снова `verify.sql`;
- на проекте `chek.base` — в SQL-редакторе Supabase (последний прогон
  02.11.2026: ожидание совпало).

## Применение

Миграции уже применены к проекту через Supabase. Для другого проекта примените
файлы из `supabase/migrations` по порядку в SQL-редакторе или Supabase CLI.
Затем задайте в `.env` приложения:

```dotenv
SUPABASE_DEMO_ENABLED=1
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Используйте **publishable** key. Secret/service_role ключи запрещены в клиентской
конфигурации. Страница «Supabase демо» доступна администратору и бухгалтеру.
