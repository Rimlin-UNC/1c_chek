# Ямастер Чек — стенд проверки качества (v1.70.38)

Разработчик и владелец идеи: **ООО «Ямастер»** · https://ymaster.ru · chek@ymaster.ru

Здесь лежат постоянные инструменты аудита приложения. Они добавлены по итогам
полной проверки v1.70.38 («найди баги, проведи стресс-тесты как профессиональные
тестировщики») и рассчитаны на то, что их будут запускать снова — при каждом
крупном изменении.

## Что чем проверяется

| Задача | Инструмент | Где |
|---|---|---|
| Статические ошибки, опечатки, мёртвый код | `ruff` (правила-ворота в `ruff.toml`) | `make lint` / `.venv/bin/ruff check app tests` |
| Уязвимости в коде (инъекции, shell, XXE) | `bandit` | `.venv/bin/bandit -r app -x app/vendor` |
| Договорённость API: коды, схема, типы | `schemathesis` — фаззинг по OpenAPI | команда ниже |
| Прикладные полезные нагрузки (SQL, XSS, CRLF, путь за каталог, SSRF, команды, шаблоны, Unicode, битый JSON) | свой стенд на TestClient | `tests/load/fuzz_sweep.py` |
| Нагрузка: RPS, p95/p99, ошибки | `locust` | `tests/load/locustfile.py` |
| Поиск предела производительности | `locust` + ступенчатая форма | `tests/load/locustfile_stepped.py` |
| Свойства чистых функций (не на примерах, а на правилах) | `hypothesis` | `tests/test_properties.py` |
| Гонки и потеря записей под параллелизмом | `pytest` + потоки | `tests/test_v17038.py` |

Всё ставится одной командой: `.venv/bin/pip install -r requirements-dev.txt`
(это `requirements.txt` плюс pytest, ruff, bandit, hypothesis, schemathesis, locust).

## Обязательно: отдельный стенд, не рабочая база

Фаззинг и нагрузка пишут в базу. **Никогда не запускайте их против базы
владельца** (`data/ymaster_check.db`). Стенд поднимается так:

```bash
cd /путь/до/репозитория
DATABASE_URL="sqlite:////путь/до/репозитория/data/load38.db" \
RATE_LIMIT_API=2000000 RATE_LIMIT_LOGIN=2000000 \
RATE_LIMIT_REGISTER=2000000 RATE_LIMIT_ONEC=2000000 \
.venv/bin/python run.py --host 127.0.0.1 --port 8001
```

Пороги частоты подняты намеренно: иначе все «пользователи» приходят с одного IP,
упираются в лимит 240 запросов в минуту, и прогон измеряет ограничитель, а не
приложение. Вход на стенде — `admin` / `admin123` (создаётся при первом старте).

## Прогоны

**1. Фаззинг по схеме API (готовый движок, ~5 минут):**

```bash
TOK=$(curl -s -X POST http://127.0.0.1:8001/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')

.venv/bin/st run http://127.0.0.1:8001/api/openapi.json \
  -H "Authorization: Bearer $TOK" --workers 2 --max-time 300 \
  --report /tmp/st-report --suppress-health-check all --output-truncate true
```

Критерий: `ST101 Server error` — ноль. Остальные проверки читаются так:
`ST108 response violates schema` — ответ не совпал с документацией;
`ST202 schema-valid request rejected` — запрос по схеме отклонён (часто это
законное бизнес-правило, проверяется вручную); `ST105 undocumented content-type`
— ответ с незадокументированным типом содержимого.

**2. Свои полезные нагрузки (без сети, внутри процесса, ~10 минут):**

```bash
.venv/bin/python tests/load/fuzz_sweep.py --per-family 3
```

Стенд сам поднимает приложение в памяти на временной базе, поэтому отдельный
сервер не нужен. Критерий: ни одного 5xx и ни одного падения. Коды 4xx — это
правильный отказ, они находками не считаются.

**3. Нагрузка (20 пользователей, минута):**

```bash
.venv/bin/locust -f tests/load/locustfile.py --headless \
    --host http://127.0.0.1:8001 -u 20 -r 5 -t 60s --csv /tmp/load
```

Критерий: ноль ошибок, p95 не выше 2 с.

**4. Ступени — поиск предела:**

```bash
.venv/bin/locust -f tests/load/locustfile_stepped.py --headless \
    --host http://127.0.0.1:8001 -t 6m --csv /tmp/step
```

Старт с 40 % базового профиля, шаг +30 %, стоп при 2 % ошибок или p95 выше 2 с.
Число пользователей на момент остановки и есть предел текущей сборки.

## Что стенд НЕ делает (и почему)

* **Не трогает** обновление программы, откат, восстановление резервных копий и
  установку AdGuard: эти маршруты выполняют настоящие команды (`git`,
  `systemctl`, `sudo`) и способны сломать рабочий сервер владельца.
* **Не трогает** настройки внешних сервисов: записанный фаззером мусорный токен
  ФНС/proverkacheka заставляет следующие же запросы ходить наружу с ним.
* **Не проверяет** внешний вид страниц — для этого `html-validate` и `stylelint`
  (см. журнал тестирования `docs/ui_journal.md`).
