# Банки по API (v1.70.99 — Точка, v1.70.102 — несколько банков)

Решения — [ADR-29](ARCHITECTURE.md#adr-29) (Точка) и [ADR-32](ARCHITECTURE.md#adr-32) (несколько банков).
Задачи — T-73 ([#57](https://github.com/Rimlin-UNC/1c_chek/issues/57)), раньше — Точка в 1.70.99.

## Зачем

Бухгалтер-аутсорсер ведёт сразу несколько компаний, и у каждой — свои банки. В карточке компании он
вводит ключи каждого банка один раз. После этого выписки приходят сами раз в 6 часов, а также по кнопке
«⬇ Загрузить сейчас». Они проходят ту же проверку, что и загруженный файл:

- списания без документов (оплаты поставщикам без УПД, покупки по картам без чека) попадают в
  «Что нужно от клиента»;
- покупка по карте сотрудника становится запросом лично ему;
- пришёл документ — запрос закрывается сам.

Доступ к банку — **только на чтение** счетов и выписок. Платёжных методов в программе нет.

## Какие банки и что нужно

| Банк | Способ | Что ввести в карточке | Где взять | Спецификация |
|---|---|---|---|---|
| Точка | OAuth 2.0 или JWT-ключ | client_id и client_secret (или общее приложение сервера) либо JWT-ключ | Интернет-банк → «Интеграции и API» | developers.tochka.com |
| Т-Банк | ключ API | токен | Т-Бизнес → «Интеграции» → «Выпуск токена», доступ «Счета и выписки» | developer.tbank.ru — счета v4, выписка `/api/v1/statement` |
| Сбербанк | OAuth 2.0, токены из кабинета | client_id, client_secret, refresh_token и сертификат клиента (PEM или .p12) | Личный кабинет Sber API (developers.sber.ru), интеграция своей организации; сертификат для API — в СберБизнесе | developers.sber.ru/docs/ru/sber-api |
| Альфа-Банк | ключ API или токен доступа | ключ; сертификат — если банк его выдал | Альфа-Бизнес Онлайн → Alfa API (заявка на alfa_api@alfabank.ru) | официальный SDK github.com/alfacomdevelopment/alfa-api-sdk (MIT) |
| Модульбанк | ключ API | токен | Интернет-банк → «Услуги» → «Интеграция с банком» → «Подключение к API», права account-info и operation-history | api.modulbank.ru |

Банки первой десятки без открытого API выписок для своей компании показаны в карточке честно, без
догадок. Их выписка загружается файлом в формате 1С на экране «Банк: выписка», проверка та же:

- **ВТБ** — «Интеграционный Банк-Клиент» по договору, запросы подписываются ГОСТ;
- **Райффайзенбанк** — Raif API по заявке; спецификация выписок не публична, **требует уточнения**;
- **Газпромбанк, Россельхозбанк, ПСБ, Совкомбанк, МКБ, Банк ДОМ.РФ** — открытого API выписок нет или
  оно по отдельному договору.

## Как устроено

- **Реестр** — `app/bank/providers.py`. Для каждого банка: способы доступа, нужен ли сертификат
  клиента, подсказка, где взять ключи, и ссылка на спецификацию.
- **Обмен** — `app/bank/http.py`:
  - доверие к системным сертификатам и к сертификатам Минцифры;
  - сертификат клиента для взаимного TLS (PEM пишется во временный файл 0600, который удаляется
    сразу после загрузки);
  - понятные ошибки по виду: доступ истёк, нет прав, частые запросы, банк не отвечает, TLS.
- **Клиенты банков** — `tbank.py`, `sber.py`, `alfa.py`, `modul.py`. Формат «transactions + rurTransfer»
  (Сбер и Альфа) — общий, в `fintech.py`.
- **Выписка в формат 1С.** Каждая операция переводится в поля формата обмена с 1С. Дальше — тот же
  классификатор (`parser.classify`), сверка и запросы, что у файла. Одна и та же операция из файла и
  из API не задваивается.
- **Хранение выписок:** одна выписка в программе на счёт и месяц, она дополняется при каждой загрузке.
  Сбер и Альфа отдают выписку по дням, поэтому за одну загрузку берётся не больше 45 дней, остальное —
  в следующую.
- **«Проверить и подключить»** запрашивает у банка счета компании, а у Сбера и Альфы — ещё и ИНН. ИНН
  сверяется с карточкой компании, номера счетов запоминаются только зашифрованными.
- **Сбер: продление доступа.** Токен доступа живёт 60 минут, refresh_token — 180 дней. Программа сама
  продлевает доступ и сразу сохраняет новую пару (старый refresh_token банк держит в резерве 2 часа).
- **Сертификат клиента** (`app/bank/clientcert.py`). Принимается PEM (сертификат и ключ) или .p12/.pfx
  с паролем. Программа проверяет, что ключ подходит к сертификату и срок не истёк, затем приводит его к
  одному PEM. Хранится только зашифрованным (`bank_connections.cert_enc`). В интерфейс уходят лишь срок
  действия и короткий отпечаток. Ключи ГОСТ стандартная криптография Python не читает — для них
  программа выдаёт понятную ошибку.
- **Сводка аутсорсера** («Клиенты») показывает худшее состояние банков компании и первую ошибку с
  названием банка.

## Безопасность

Ключи, токены, сертификаты и номера счетов хранятся только в зашифрованных колонках
(`services.secretbox`). В браузер уходят только признаки «задан», последние 4 цифры счетов и срок
сертификата. Ключи в журнал не пишутся. Проверку сертификата сервера отключить нельзя.

## Как проверено

Тесты работают **только на синтетике** (ADR-14). Банки имитируются (`httpx.MockTransport`) по форматам
их открытых спецификаций — `tests/test_bank_multi.py`, `tests/js/bank_multi.test.js`. Проверено:

- подключение, курсоры и страницы, продление токенов Сбера;
- сверка ИНН, ошибки банков, права доступа;
- дубли между файлом и API, сертификаты PEM и PKCS#12.

Сертификаты для тестов выпускаются в самом тесте. Подключение на настоящих ключах банков **требует
уточнения** у владельца: у программы нет доступа к банкам из среды разработки.
