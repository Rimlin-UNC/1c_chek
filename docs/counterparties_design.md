# Контрагенты и договоры: карточка из документов, реквизиты одним кликом

Проект задач **T-80** ([#65](https://github.com/Rimlin-UNC/1c_chek/issues/65)) и **T-81**
([#66](https://github.com/Rimlin-UNC/1c_chek/issues/66)). Номера выпусков — по
[ADR-44](ARCHITECTURE.md#adr-44). Порядок, заданный владельцем 07.11.2026: сначала ближайшие
этапы плана (T-62 — печатная форма УПД), затем T-80, затем T-81.

## 1. Что просит владелец
**Реализовано 08.11.2026 в выпуске 1.71.0 (ADR-48):** этап 1 закрыт — три новые таблицы, `app/counterparties/*`, экран «Контрагенты», проверка по ИНН, падежи, блоки, дубли и изоляция компаний. Ниже проект сохранён как источник решения; раздел 8 по-прежнему содержит вопросы владельца для T-81.


> «Контрагенты берутся из УПД и счетов, проверяются нашим блоком проверки компаний по ИНН, по ним
> создаётся карточка предприятия с полной информацией; при подготовке договора, счёта или платёжки
> данные вставляются одним кликом (образцы — блок реквизитов стороны и преамбула договора).»
> — запрос владельца 07.11.2026, [#65](https://github.com/Rimlin-UNC/1c_chek/issues/65)

> «Папка „Документы“ с подпапкой „Договоры“ и заполнением форм под конкретные условия; изучить
> лучшие программы рынка и развивать планомерно.» — [#66](https://github.com/Rimlin-UNC/1c_chek/issues/66)

Критерий приёмки обоих этапов — то, что владелец видит: **ввёл ИНН (или пришёл УПД) → карточка
заполнилась сама → в договоре, счёте и платёжке реквизиты стоят на своих местах**, а
предупреждения о надёжности видны до подписания.

## 2. Что уже есть в программе (не начинаем с нуля)

| Что | Где | Что даёт для T-80 |
|---|---|---|
| Проверка компании по ИНН (Checko, выписка ЕГРЮЛ/ЕГРИП ФНС) | `app/services/checko.py`, `app/services/fns.py`, `app/services/fns_refs.py`, карточка компании | готовые поля: наименование, ОГРН, ИНН, КПП, адрес, руководитель, статус, недостоверность, массовый адрес; квота Checko — 100 запросов в сутки |
| Первичка: УПД и счета-фактуры 5.03 | `app/primary/*` (продавец и покупатель, строки, суммы) | источник контрагентов: продавец и покупатель каждого документа |
| Банковская выписка | `app/bank/*` (плательщик, получатель, ИНН, БИК, счета) | источник банковских реквизитов и БИК для проверки по справочнику Банка России |
| Справочник БИК | `app/bank/*` (банк по БИК), `app/services/fns_refs.py` | «банк по БИК» — название, корсчёт |
| Карточка компании и реквизиты организации | `app/models.py: Company`, `card_json` | «своя сторона» договора и платёжки |

Чего нет и что нужно сделать: справочника контрагентов, падежей, подписанта, блоков текста и
объединения дублей.

## 4. Данные (только добавляющие изменения, ADR-03, ADR-09)

| Таблица | Что хранит |
|---|---|
| `counterparties` | карточка контрагента: компания (владелец карточки), ИНН, КПП, ОГРН, полное и краткое наименование, организационная форма, адрес (строкой и по полям), статус, признаки риска (JSON), источник (manual, upd, bank, checko), когда проверяли и чем, подписант (должность, ФИО, основание), банковские реквизиты (счёт, БИК, банк, корсчёт), заметка; уникальность — компания + ИНН |
| `counterparty_bank_accounts` | счета контрагента: расчётный счёт, БИК, банк, корсчёт, основной; уникальность — счёт |
| `counterparty_aliases` | варианты написания (из УПД, из выписки) — для объединения дублей без потери истории |
| `contract_templates` (T-81) | шаблон: название, вид (договор, счёт, акт), тело HTML или DOCX, список своих полей |
| `contracts` (T-81) | документ из шаблона: номер, дата, две стороны (контрагент и своя компания), значения своих полей, тело на момент подписания (снимок), кто создал |

Внешних ключей на старые таблицы нет; удаление контрагента не удаляет документы первички —
только связь. Минимум персональных данных: ФИО подписанта — это данные о должностном лице
организации, они и так есть в ЕГРЮЛ и в договоре.

## 5. Модуль

```
app/counterparties/
  models.py    — таблицы выше
  service.py   — карточка, поиск, объединение дублей, изоляция компаний (ADR-20)
  sources.py   — откуда взять контрагента: УПД (продавец/покупатель), выписка, счёт, ИНН
  verify.py    — проверка по ИНН: наш блок (Checko, выписка ФНС), БИК — по справочнику ЦБ
  grammar.py   — падежи (родительный, дательный, предложный) для наименований и ФИО
  blocks.py    — «Реквизиты стороны», «Преамбула договора», «Для платёжного поручения»
  router.py    — /api/v1/counterparties/*
```

Правила:

- **Компания — владелец карточки** (ADR-20): бухгалтер видит контрагентов своей и назначенных
  компаний; один и тот же ИНН у двух компаний — две карточки (у аутсорсера свои клиенты).
- **Автозаполнение — предложение, а не запись**: из УПД и выписки контрагент появляется
  «найденным», карточка создаётся по действию бухгалтера (или сразу, если запись дешёвая и
  без персональных данных; решение — при разработке).
- **Проверка по ИНН — по кнопке и при создании**: Checko (100 запросов в сутки — считает
  `fns_quota`), выписка ЕГРЮЛ/ЕГРИП ФНС — запасной путь; БИК — по справочнику Банка России,
  без внешних запросов.
- **Падежи** — правила, без нейросетей: «ООО „Ромашка-Строй“» → «Общества с ограниченной
  ответственностью „Ромашка-Строй“»; ФИО — по правилам склонения; незнакомое — не склоняем, а
  показываем как есть и даём поправить руками (в карточке поле «в родительном падеже»).
- **Дубли** — по ИНН, затем по нормализованному наименованию и адресу; объединение — с переносом
  счетов, вариантов написания и связей, без удаления документов.
- **Шаблоны (T-81)** — метки вида `{Заказчик.Реквизиты}`, `{Заказчик.Преамбула}`,
  `{Исполнитель.Реквизиты}`, свои поля `{Номер контракта}`, `{Основание (44-ФЗ)}`. Тело документа
  на момент подписания сохраняется снимком: правка шаблона не меняет уже подписанные документы.

## 7. Критерии приёмки

- pytest: источники (УПД, выписка, ручной ИНН), проверка по ИНН и БИК, падежи (в том числе
  незнакомые наименования), блоки текста, объединение дублей, изоляция компаний — **SQLite и
  PostgreSQL**; только синтетика (ADR-14).
- Vitest: карточка контрагента, блоки «Скопировать», предупреждения о надёжности, поиск дублей.
- Контракт «интерфейс ↔ API» (`tests/test_ui_api_contract.py`) — новые вызовы интерфейса описаны
  маршрутами; новый экран — в обе матрицы ролей (`app/services/rbac.py` и `app/static/js/app.js`).
- Пределы: не больше 5000 контрагентов на компанию без постраничности; проверка по ИНН — не чаще
  квоты Checko; запрос по ИНН — с задержкой антибана, как у проверки чеков.

## 8. Требует уточнения

- **Образцы договоров** (поставка, услуги, контракт по 44-ФЗ) — от владельца (T-81, #66).
- **Нужен ли DOCX** или достаточно HTML и PDF: DOCX требует библиотеки записи (python-docx —
  ещё одна зависимость на сервер 2 ГБ), HTML+PDF печатается браузером, как в T-62.
- **Счёт и платёжка**: платёжное поручение — это форма банка (0401060), реквизиты для неё
  собираются блоком «Для платёжного поручения»; печатать саму форму или отдавать файл банку —
  решает владелец.
- **Хранение договоров**: в базе (снимок тела) или файлом в папке документов компании — влияет на
  резервные копии; предлагается в базе, как первичка.
