# Что требует приложение (технический минимум)

| Требование                                    | Зачем                                                        |
|-----------------------------------------------|--------------------------------------------------------------|
| Постоянно работающий процесс Python (uvicorn) | Это не PHP-«запрос-ответ», сервер живёт постоянно            |
| WebSocket (/ws/status)                        | Живые обновления статусов проверки чеков у всех пользователей |
| HTTPS                                         | Обязательно: камера телефона (сканирование QR) работает ТОЛЬКО по HTTPS |
| Постоянный диск под файл БД                   | Чеки, пользователи, журнал аудита                            |
| Входящий HTTP от 1С с токеном                 | Push/pull интеграция: 1С забирает чеки по HTTPS              |
| Root-доступ (UFW, fail2ban, Nginx limit_req)  | Защита от перебора и DoS — 6 слоёв, настроенных на сервере   |
| Размещение в РФ                               | В БД имена сотрудников — персональные данные (152-ФЗ)        |

# ВАЖНО: «хостинг с базой данных» не даёт преимуществ

Приложение УЖЕ имеет собственную встроенную базу (SQLite): файл создаётся и
обслуживается само, внешний MySQL/PostgreSQL не нужен. Бэкап — один файл
(data/ymaster_check.db). Поэтому выбирать хостинг «потому что там есть база
данных» не требуется. Решающий фактор — возможность запустить постоянный
Python-процесс с WebSocket и root-доступом для защиты.

# Сравнение вариантов

## A. Текущий сервер 94.183.236.179 (Ubuntu 24.04) — деплой туда
Стоимость: 0 ₽/мес.
+ Ubuntu 24.04 — точное совпадение с deploy.sh; DNS chek.ymaster.ru уже
  указывает сюда — вообще ничего не переключать.
+ Бесплатно, сервер уже оплачен.
− РИСК: deploy.sh рассчитан на ЧИСТЫЙ сервер — он ставит Nginx, включает
  UFW (снаружи только 22/80/443) и fail2ban. Если на сервере уже работают
  другие сайты/сервисы (например, ymaster.ru) — брандмауэр может закрыть
  их порты, а конфиг Nginx — конфликтовать. Требуется предварительный аудит
  и «бережный» режим установки (--no-nginx + ручной server_name).
− Нарушает требование «не трогать сервер».
Вердикт: возможно, но с осторожностью и проверками.

## B. Отдельный маленький VPS под chek.ymaster.ru  ← РЕКОМЕНДАЦИЯ
Стоимость: ~200–400 ₽/мес (Timeweb: от 180–272 ₽/мес Москва NVMe;
Beget — месяц бесплатного теста; reg.ru/SpaceWeb — сопоставимо).
+ Полная изоляция: ваш существующий сервер НЕ ТРОГАЕМ ВООБЩЕ.
+ Чистая Ubuntu 24.04 — deploy.sh встанет идеально одной командой:
    sudo bash deploy.sh --domain=chek.ymaster.ru --with-ssl=chek.ymaster.ru
  (сам поставит Nginx+TLS+UFW+fail2ban, создаст сервис, выдаст админ-пароль).
+ Все 6 слоёв защиты работают как задумано; 80/443 свободны.
+ Снапшоты/бэкапы панелью хостера в один клик.
+ Данные в РФ (152-ФЗ); домен уже ваш, TLS бесплатный (Let's Encrypt).
− Небольшая ежемесячная плата.
Откат полностью обратим: вернуть A-запись на старый IP — всё как было
(рекомендуется заранее поставить TTL 300 секунд).
Вердикт: самый безопасный и предсказуемый путь.

## C. Обычный shared-хостинг «с базой данных» (панель, PHP/MySQL)
Стоимость: обычно уже оплачен вместе с сайтом.
+ Не трогает ваш сервер.
− Технически НЕ ПОДХОДИТ: нет постоянно живущего Python-процесса,
  нет WebSocket, нет root (значит — никакой UFW/fail2ban/limit_req),
  HTTPS-сертификат и заголовки безопасности не под нашим контролем.
  Приложение просто не запустится или будет работать с потерей функций.
Вердикт: исключить. Идея «на хостинге уже есть база» — не аргумент:
  приложению внешняя база не нужна (см. выше).

## D. Зарубежные облачные PaaS (Render, Railway, Fly.io, …)
Стоимость: полноценного бесплатного нет ($5–15/мес).
+ Не трогает ваш сервер.
− Бесплатные тарифы «засыпают» и стирают диск при перезапуске → ПОТЕРЯ ЧЕКОВ.
− Оплата российскими картами затруднена, доступ из РФ нестабилен.
− Персональные данные сотрудников за рубежом — риск по 152-ФЗ.
Вердикт: не рекомендуется для бизнес-приложения.

## E. Превью-песочница (текущая демонстрация)
Только для просмотра и приёмки: среда временная, данные не гарантируются.
Вердикт: не для продакшена.

# Рекомендация ООО «Ямастер»

Вариант B — отдельный VPS минимальной конфигурации:
  Ubuntu 24.04, 1 vCPU, 1–2 ГБ RAM, 15–20 ГБ NVMe, дата-центр в РФ.
Приложение лёгкое: распознавание QR выполняется в браузере телефона,
сервер только хранит и проверяет — 1 vCPU хватает на небольшой офис.

Порядок перехода (15 минут):
  1. Заказать VPS (Ubuntu 24.04).
  2. В DNS-панели ymaster.ru заранее снизить TTL до 300 с.
  3. Поменять A-запись chek.ymaster.ru → IP нового VPS.
  4. Одна команда на новом сервере:
       curl -fsSL https://raw.githubusercontent.com/Rimlin-UNC/1c_chek/arena/01a0caaa-1c-chek/deploy.sh -o deploy.sh
       sudo bash deploy.sh --domain=chek.ymaster.ru --with-ssl=chek.ymaster.ru
     (если репозиторий приватный: GITHUB_TOKEN=ghp_xxx sudo -E bash deploy.sh ...)
  5. Войти admin/admin123, сменить пароль, создать приглашения.
Откат: вернуть A-запись на 94.183.236.179 — прежнее состояние.

Если будет выбран вариант A (текущий сервер) — сначала аудит одной командой
(результат прислать для анализа):
  ssh root@94.183.236.179 'ss -tlnp; echo ---; nginx -t 2>&1; echo ---; ufw status; echo ---; systemctl list-units --type=service --state=running | grep -Ei "nginx|apache|php|mysql|postgres|caddy"'
и затем установка в бережном режиме (--no-nginx с ручным включением сайта).
