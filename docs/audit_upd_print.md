Дата: 2026-11-20. Предмет: печатная форма УПД (`app/primary/printupd.py`), её сверка с PDF из ЭДО,
заполнение полей из XML, правило «без электронной подписи», билет печати, мобильный вид, тесты.

Эталон геометрии: `ON_NSCHFDOPPR_…20260908….pdf` («Интернет Решения», статус 1, НДС 22 %).
Второй образец (`…2BE66C2…20260512….pdf`, ИП Фёдоров, без НДС) использован только для проверки
чисел и правила «без НДС»: геометрически образцы расходятся (см. §7).

## 2. Критический дефект: бланк печатался на двух страницах

`@page { size: A4 landscape }` — это **595.28 pt** по высоте, а лист бланка — **594.96 pt**.
Полпункта не хватало, и хвост («ООО "Интернет Решения"», «М.П.») уходил на вторую страницу;
на экране дефект не виден, потому что лист там не разрезается.

Исправлено двумя мерами, обе нужны:

1. `@page { size: 841.92pt 594.96pt; margin: 0 }` — размер страницы в точных пунктах.
2. Содержимое ужато ниже листа: `@media print { table.page { height: 593.6pt } }` плюс высоты
   полос, снятые с PDF (§4).

Проверка: `page.pdf()` при 841.92 × 594.96 pt → **1 страница**, «М.П.» на y = 537.3
(в PDF 535.2).

## 3. Методика сверки

* Рендер настоящего бланка: XML → `service._store` → `printupd.html` → Chromium
  (`--no-sandbox`, viewport 1123 px, `emulateMediaType('print')`) → PDF 841.92 × 594.96 pt.
* Точки = px / (96/72). Предупреждение: без `emulateMediaType('print')` и viewport 1123 px
  замеры врут примерно в 1.75 раза.
* Из PDF извлекались: текстовые строки с координатами (`get_text('dict')`), горизонтальные и
  вертикальные линии (`get_drawings()`), ширины 16 граф (шаг вертикальных линий).
* Сравнение — по 18 якорям (`search_for`) и по картам горизонтальных линий.

## 5. Заполнение полей из XML

`auto_from()` на представленном XML заполняет 15 из 48 полей:

```
seller_address · seller_subject · buyer_address · buyer_subject · shipper · consignee
basis · shipment_doc · transfer_date · transfer_position · transfer_sign · transfer_name
accept_date · signer_chief · signer_chief_role
```

Остальные 33 поля — либо ручные (исправление, платёжный документ, валюта, банковские
реквизиты), либо вычисляемые из строк документа (итоги, ставки), либо относятся к покупателю,
которого в конкретном XML нет. Для УПД с двумя подписантами (`/tmp/two.xml`) дополнительно
заполняются `accept_position` / `accept_sign` / `accept_name` — «ГЕНЕРАЛЬНЫЙ ДИРЕКТОР ·
электронно · ШПАКОВ РОМАН ВЛАДИМИРОВИЧ», как в PDF.

Правка пользователя имеет приоритет над автозаполнением и сохраняется в `print_json`
(`stored()` не считает «auto» правкой).

## 6. Правило «без электронной подписи»

Блок «ДОКУМЕНТ ПОДПИСАН ЭЛЕКТРОННОЙ ПОДПИСЬЮ» (сертификаты, «ОТПРАВЛЕНО»/«УТВЕРЖДЕНО»,
идентификатор, оператор ЭДО, y 511–578 в PDF) в бланк не печатается. Поля `edo_*` остаются в
окне заполнения и в `print_json`. Разница текстового слоя нашего PDF и PDF из ЭДО — **5 строк**,
все внутри этого блока.

Следствие для геометрии: низ бланка в PDF занят блоком ЭП (≈65 pt). Поскольку по требованию
владельца его не печатают, 1:1 по координатам ниже y ≈ 508 недостижим по определению — «М.П.»
в PDF стоит на 535.2 между двумя отметками М.П., а у нас — под «Наименованием экономического
субъекта». Это осознанное расхождение, а не дефект.

## 8. Билет печати (`?ticket=`) — безопасность

Проверено:

* Билет подписан `SECRET_KEY`, живёт 30 минут, привязан к `doc` и имеет `scope: "print"`.
* `decode_token()` отвергает любые токены со `scope` — билет нельзя предъявить как токен доступа.
* Права те же, что у окна печати: бухгалтер и администратор; сотруднику 403, чужой/просроченный
  билет 401. Отказ отдаётся **HTML-страницей** с объяснением, не JSON.
* Бланк отдаётся с `Cache-Control: no-store`.

Найдено и исправлено в ходе аудита: адрес бланка содержит `?ticket=…`, и браузер отправлял его
в заголовке `Referer` при загрузке `/js/primary_print_page.js` — одноразовая ссылка оседала в
журналах доступа сервера и прокси. Добавлено `<meta name="referrer" content="no-referrer">`.
Внешних ресурсов бланк не подгружает (проверено: в HTML нет ни одного `http(s)://`).

Остаточный риск (принят): билет не отзывается до истечения 30 минут и попадает в историю
браузера на устройстве пользователя; отзыв потребовал бы хранилища одноразовых меток.

## 9. Мобильный вид (Android)

Viewport 390 × 844, `isMobile`:

* лист масштабируется (`zoom: .52`), ширина листа 584 px при прокрутке вбок — раскладка цела;
* кнопка «🖨 Печать / сохранить в PDF» — 378 × 32 px, панель видна;
* подсказка «В окне печати выберите «Сохранить как PDF»…» видна на телефоне.

Известное ограничение (не дефект нашего кода): Chromium для Android намеренно не открывает
системное окно печати из `window.print()`; путь ⋮ → «Поделиться» → «Печать» объяснён словами
на самой странице (v1.73.5).

Замечание по доступности: кнопка получилась 32 px по высоте при рекомендации 44 px. Так было и
до аудита; вынести в отдельную задачу.

## 11. Что осталось за рамками аудита

1. Кнопка печати на телефоне 32 px вместо 44 (эргономика, не геометрия).
2. Билет печати не отзывается до истечения (см. §8).
3. Дрейф ≤ 6.2 pt остаётся по четырём якорям, и все они — в шапке: «Универсальный» −3.7,
   «Приложение N 1» −6.2, приложение к постановлению −6.0, «Покупатель» −3.0. Нижняя половина
   сходится в пределах 2.9 pt. Доводить шапку до нуля через `padding-top` листа не стоит: это
   сдвинет вниз весь бланк, а блок ЭП в PDF всё равно не печатается (§6).
