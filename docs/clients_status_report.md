## C. Технические заметки к этапу 1 (для реализации)

- `CompanyCreate` уже допускает создание без ИНН (`inn_is_valid("")` → `True`).
- Дубли: `_canonical_taken` (канон имени) и `_inn_taken` (ИНН) — переиспользовать.
- Для бухгалтера: `POST /api/v1/companies` с новым правилом — создаёт компанию и
  **в той же транзакции** строку `accountant_clients(user_id=автор, company_id=новая)`,
  иначе бухгалтер создаст компанию, которую сам не увидит (это и есть главная ловушка).
- Ограничения: `MAX_CLIENTS = 500` на бухгалтера (`app/clients/service.py`) — проверять до создания.
- Журнал: `company_created` + `clients_access_set` (или одно событие с признаком «сам себе»).
- Матрицы ролей: экран `clients` уже у бухгалтера; новых экранов не добавляем.
- Схема БД: **не меняется** — только права и логика. Откат — обычный.
