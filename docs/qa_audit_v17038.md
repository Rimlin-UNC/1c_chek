# Отчёт о полной проверке приложения «Ямастер Чек», выпуск v1.70.38

Разработчик и владелец идеи: **ООО «Ямастер»** · https://ymaster.ru · info@ymaster.ru
Дата проверки: 21 октября 2026 г. · ветка `arena/071f4163-1c-chek`

Задача владельца: *«Проверь полностью приложение на баги и ошибки, проведи стресс
тесты и прочее что обычно делают профессиональные тестировщики (возьми за основу,
найди информацию на гитхабе и на хаббре) и исправь ошибки. Возможно там есть уже
готовые движки либо ещё что-то что упростит задачу в программировании и тесте»*.

**Итог: найдено 18 дефектов, все 18 исправлены и закреплены тестами.** Проверка
велась готовыми движками, а не самодельными скриптами; инструменты остались в
репозитории (`tests/load/`, `tests/test_properties.py`, `ruff.toml`,
`requirements-dev.txt`), чтобы прогон можно было повторить.

## 4. Нагрузочное тестирование

Стенд: 2 ядра, SQLite (WAL, `busy_timeout=5000`, пул 20+60), отдельная база,
пороги частоты подняты через `.env` — иначе измерялся бы ограничитель, а не
приложение. Профиль: вход, список чеков, приём чека по QR, аналитика, участники
Чек-Пула, поиск контрагентов, журнал.

**20 пользователей, 60 секунд, добавление по 5 в секунду:**

| Операция | Запросов | Ошибок | p95 | Максимум |
|---|---|---|---|---|
| GET /receipts?page | 607 | 0 | 34 мс | 100 мс |
| POST /receipts/scan | 368 | 0 | 25 мс | 110 мс |
| GET /dashboard/stats + /recent | 506 | 0 | 30 мс | 94 мс |
| GET /pool-admin/participants | 188 | 0 | 18 мс | 84 мс |
| GET /companies/similar | 92 | 0 | 12 мс | 76 мс |
| GET /admin/system | 99 | 0 | 36 мс | 110 мс |
| POST /auth/login (PBKDF2) | 20 | 0 | 300 мс | 300 мс |
| **Всего** | **1 880** | **0** | **31 мс** | **300 мс** |

RPS 31,5, p99 170 мс. **Ступенчатый прогон** (45 с на ступень, шаг +30 % от 40 %
базового профиля): 9 260 запросов, **0 ошибок**, 59 RPS, p95 15 мс, максимум
577 мс на входе. Предел по критериям «2 % ошибок либо p95 > 2 с» на этой
конфигурации не достигнут — остановка произошла по числу пользователей (60),
заданному как потолок песочницы.

Отдельно проверена гонка записи журнала аудита: 16 потоков × 40 записей — 640 из
640 сохранены, номера уникальны; повторный прогон 960 из 960.

## 5. Проверено и отвергнуто (ложные срабатывания)

* **ST202 «запрос по схеме отклонён» (28 случаев).** Ручная проверка: законные
  бизнес-отказы — неверный текущий пароль (403), случайный идентификатор (404),
  мусор в проверке passkey (422). Схема описывает форму запроса, а не правила.
* **32 операции отвечают только 401/403** — защищённые маршруты без анонимного
  доступа; предупреждение снято описанием кодов в схеме.
* **Первый прогон своего стенда: 438 «находок», из них 354 — ошибки самого
  стенда.** Одиночные суррогаты и `Infinity` не проходят через `json.dumps`,
  сырые CRLF в пути ломают HTTP-клиент — запрос не доходил до сервера. Стенд
  исправлен (битый JSON сырыми байтами, нагрузка в путь URL-кодированной),
  повторный прогон чист. Вывод для будущих проверок: находку со статусом −1
  надо сначала воспроизвести вручную.
* **Фаззинг настроек интеграций самоотравляет стенд**: мусорный токен ФНС/
  proverkacheka заставлял следующие запросы ходить наружу. Внешние интеграции
  исключены из развёртки — их валидация покрыта юнит-тестами и тестами ротации
  источников.

## 6. Как повторить проверку

Полная инструкция — в `tests/load/README.md`. Коротко:

```bash
.venv/bin/pip install -r requirements-dev.txt

# статика и уязвимости
.venv/bin/ruff check app tests
.venv/bin/bandit -r app -x app/vendor

# свойства и замки аудита
.venv/bin/pytest tests/test_properties.py tests/test_v17038.py -q

# свой стенд с полезными нагрузками (без сети, внутри процесса)
.venv/bin/python tests/load/fuzz_sweep.py --per-family 3

# стенд для фаззинга и нагрузки — ОТДЕЛЬНАЯ база, не рабочая
DATABASE_URL="sqlite:////путь/до/data/load38.db" RATE_LIMIT_API=2000000 \
RATE_LIMIT_LOGIN=2000000 RATE_LIMIT_REGISTER=2000000 RATE_LIMIT_ONEC=2000000 \
.venv/bin/python run.py --host 127.0.0.1 --port 8001

# фаззинг по схеме API (готовый движок)
.venv/bin/st run http://127.0.0.1:8001/api/openapi.json -H "Authorization: Bearer $TOK" \
    --workers 2 --max-time 300 --suppress-health-check all

# нагрузка и поиск предела
.venv/bin/locust -f tests/load/locustfile.py --headless --host http://127.0.0.1:8001 -u 20 -r 5 -t 60s
.venv/bin/locust -f tests/load/locustfile_stepped.py --headless --host http://127.0.0.1:8001 -t 6m
```

Критерии приёмки: ноль 5xx, ноль ошибок нагрузки, p95 не выше 2 с, ворота ruff
зелёные, bandit High/Medium — ноль, реестр долга не растёт.
