# Расширение мониторинга сервера — проект (#106)

Задание #106 называет работу T-91; этот номер уже занят другой задачей в `02_roadmap.csv`. Для исключения путаницы новая строка реестра — T-108, прежнюю не меняем. Это проект, а не утверждение, что весь функционал уже работает.

## Принципы

- Только администратор; текущий API `GET /api/v1/admin/server-monitor` закрыт `require_admin` и выдаёт `Cache-Control: no-store`. Новые данные не должны ослаблять права или расширять доступ обычным пользователям.
- Не ставить пакеты, службы, root-права и сетевые порты на рабочий сервер автоматически. Не влиять на ФНС, антибан, очереди и данные чеков. Ошибка мониторинга не должна блокировать запуск приложения.
- Измеряется пространство имён процесса, а не гарантированно вся ВМ. CPU, память, сеть и монтирования могут иметь разную видимость; обнаружение контейнера не является доказательством его отсутствия. Виртуальные интерфейсы могут учесть одни и те же байты многократно.
- Недоступность и неполный период не превращать в ноль. Частота, время снимка и перерывы сбора должны быть видны. При сбросе, смене интерфейса, перезагрузке или недостаточной истории нельзя выдавать точный прогноз.
- Измерения счётчика интерфейса — оценка, не счёт провайдера: непонятны направление тарификации, интерфейс, исключения и единицы. 1000 ГБ по заданию — ориентир, не доказанная квота; SI ГБ = 10⁹ байт, GiB = 2³⁰ байт.

## Первый этап: снимок по требованию (черновик 1.72.20)

Существующие CPU, MemAvailable и файловая система каталога дополнены разбивкой CPU user/system/iowait/steal, load average, uptime, swap и короткими скоростями/дельтами ошибок сетевых интерфейсов. Данные Linux `/proc` только читаются, счётчики из разных интерфейсов не суммируются, loopback исключён. Замер не запускается при открытии страницы, не записывается в БД и не создаёт фоновой службы. Частичные результаты допустимы; неточный 250-мс замер — диагностический, а не тарификация.

## Второй этап: чтение истории vnStat (черновик 1.72.21)

Опционально приложение по кнопке администратора читает JSON уже установленного vnStat по одному выбранному интерфейсу, отдельно за три месяца и 31 день. Два subprocess без оболочки и с тайм-аутом; кеш по интерфейсу на 60 с; источник и границы явно обозначены, свежесть не подтверждена: JSON не определяет часовой пояс демона. Ориентир 1000 десятичных ГБ и предупреждения показывают сумму RX+TX как наблюдение, не подтверждённый счёт. Полноту истории и условия тарифа приложение доказать не может; оставшийся объём и прогноз не показывает. На тестовой отдельной базе проверен реальный бинарник vnStat 2.12, но рабочая ВМ не исследована.

## Дополнительный снимок (черновик 1.72.23)

Из того же statvfs доступны inode каталога приложения; короткий I/O берётся только по точному major/minor из `/proc/diskstats`. Сброс или отсутствие сопоставления означает недоступность. Дополнительно показаны задачи планировщика с потоками, TCP-сокеты с слушающими, переключения контекста и swap I/O. Это не топ процессов, не все тома и не история; виртуальный слой и физическое устройство могут отличаться.

## Процессы по требованию (черновик 1.72.24)

Только администратору: два ограниченных прохода по `/proc/PID/stat`, максимум 256 PID, без командных строк и без истории. CPU считается по времени и тикам каждого процесса с проверкой starttime; RSS не равен уникальной памяти. Возврат и права procfs могут сделать данные неполными; на целевой ВМ нагрузка и видимость не подтверждены.

## Следующие этапы — ещё не реализованы

1. Согласовать источник и условия месячного учёта: интерфейс(ы), RX/TX или только исходящий, часовой пояс и начало расчётного периода, единицы и применимость лимита к публичному трафику. Пока параметры не подтверждены, явно обозначать расчёт как неполный и не показывать остаток/прогноз как точные.
2. Спроектировать независимый устойчивый к перезагрузке сбор (возможен отдельно установленный `vnstat`, только чтение его документированного JSON) с контролем возраста и полноты данных, безопасной конфигурацией и ошибками; задокументировать ручную установку и обратимый откат. Тестировать разрывы, смену интерфейса, счётчики после рестарта, пересечение месяца, переключение времени и несоответствие тарифу. Не хранить историю в памяти процесса и не делать несколько конкурирующих сборщиков на нескольких web-worker.
3. История, графики и пороги потребуют ограниченного хранения, retention, выборок и проверки доступности; нельзя называть показания до начала сбора полными, а 7/30-дневные графики — доступными. Ресурсы измерить на целевой ВМ 1 vCPU / 2 GiB, а не утверждать ≤1% без замера. Подробные логи раскрывают информацию и потребуют отдельной оценки прав и стоимости. Снимок процессов реализован ограниченно и только по кнопке; рабочая ВМ не проверена.
4. Файловые системы и inode: список монтирований и безопасное чтение без зависания на недоступных/сетевых томах, классификация и тесты; диск каталога приложения не равен всем дискам или БД на другой машине. IOPS/await/%util — счётчики блочных устройств, не заполненность раздела; сопоставление устройств и счётчиков требует проверки.
5. Графики адаптивны и доступны текстом, единицы и временные интервалы подписаны; отсутствие метрики не зелёное состояние. При реальной истории показывать пробелы вместо интерполяции и ограничивать объём выборки. Уведомления, несколько ВМ и сбор хоста из контейнера — отдельные этапы, не обещаны текущим снимком.

## Источники

- [Документация ядра Linux о `/proc`](https://docs.kernel.org/filesystems/proc.html): значения и ограничения счётчиков; `iowait` может уменьшаться, `steal` — ожидание виртуального CPU.
- [vnStat manual](https://humdi.net/vnstat/man/vnstat.html): отдельный daemon накапливает статистику выбранных интерфейсов; клиент лишь читает историю и JSON.
- [vnStat configuration](https://humdi.net/vnstat/man/vnstat.conf.html): начало расчётного месяца и хранение настраиваются, автоматически предполагать условия тарифа нельзя.
- [Prometheus: instrumentation](https://prometheus.io/docs/practices/instrumentation/): число рядов и меток влияет на память и ресурсы; для маленькой ВМ не устанавливать полноценную систему без измерения стоимости.
