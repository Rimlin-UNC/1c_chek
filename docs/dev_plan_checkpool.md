# Дорожная карта v2 — «Чек-Пул» на chek.ymaster.ru (без Telegram)

> Разработчик и владелец идеи: ООО «Ямастер» · https://ymaster.ru · info@ymaster.ru
> Статус: действующий план · база: v1.30.0 · концепция: `docs/plan.md` (обе части:
> «Чек-Пул» + веб-платформа с личными кабинетами и антифродом)
> Версия плана: v2 (2026-10-06) — сменила v1 «с Telegram» по решению заказчика.

---

## 0. Изменение концепции

**Было (план v1):** главный канал приёма чеков — Telegram-бот, сайт — дополнение.

**Стало (план v2):** весь «Чек-Пул» живёт **только на chek.ymaster.ru** —
публичная форма, личный кабинет гостя/участника, реферальные ссылки, панель
безопасности и подбор для компаний. Телеграм-канал — **на паузе**.

**Что наследуем от Этапа 1 (v1.30.0, выполнен):**
- таблицы `pool_users` / `pool_receipts` / `pool_items` / `pool_points`
  (UNIQUE fn+fd+fp, статусы, задел под гео/отрасли/компании) — канал приёма
  в модели не прописан, бот лишь источник `source='telegram_bot'`;
- пайплайн `app/pool/ingest.py`: QR → дедуп → лимит → движок источников
  (ФНС GetTicket → Честный Знак, без квот) → статус и баллы — работает
  с любого канала, веб подключится без единой правки пайплайна;
- журнал баллов, оферта, админ-маршруты `/api/v1/pool-admin/*` и карточка
  в Настройках.

**Что делаем с ботом:** код сохраняется в проекте (`telegram_bot.py`,
интеграция пула), приём в пул через бота выключен флагом `pool_enabled`
и отдельной пометкой канала. Вернуть можно одной кнопкой — это наш резервный
канал на случай, если решим возобновить.

## 1. Принципы внедрения (не ломаем основную программу)

1. **Отдельный контур.** Пул — свои модули (`app/pool/…`), свои таблицы
   (`pool_*`), свои роуты (`/api/v1/public/*`, `/api/v1/pool*`). Ядро
   (чеки компаний, 1С, АО-1, роли) не изменяется.
2. **Флаги на всё.** Каждый этап включается настройкой; по умолчанию выключен —
   деплой на боевой 94.183.236.179 безопасен, включаем после проверки.
3. **Переиспользуем ядро:** `parse_qr` (services/qr.py), движок источников,
   jsQR в браузере (сканер уже в PWA), секреты/шифрование (secretbox),
   аудит `log_action`, rate-limit, резервные копии БД.
4. **Миграции только добавляющие** — продакшн-БД никогда не требует ALTER.
5. **Каждый этап = релиз:** полный прогон тестов, харнесс, CHANGELOG/
   WHATS_NEW/инструкция, возможность отката (бэкап перед миграцией).
6. **Гость — первоклассный участник.** Регистрация не требуется, чтобы сдать
   первый чек (снижение трения — ключевой тезис plan.md). Аккаунт появляется,
   когда человеку важен баланс/история/рефералы.

## 2. Архитектура на chek.ymaster.ru

```
Публичная зона (без входа)              Личный кабинет участника
├─ #/public  приём чека                 ├─ #/my  дашборд (баллы, цель)
│   ├ строка QR (вставка/ввод)           ├─ #/my/receipts мои чеки (PDF/CSV)
│   ├ фото QR (jsQR в браузере)          ├─ #/my/invite приглашения (этап 6)
│   └ ссылка из приложения ФНС           ├─ #/my/points баллы и вывод
└─ /r/КОД  реферальный вход (этап 6)    └─ #/my/profile профиль (email, пароль)

Админ-зона (существующая Настройки + новые страницы)
├─ Настройки → «🧩 Чек-Пул» (уже есть: флаг, счётчики)
├─ #/pool-admin  очередь модерации, поиск по пулу (этап 4)
└─ #/fraud  сигналы, risk-score, кластеры (этап 5)

Бэкенд: app/pool/
├─ ingest.py (пайплайн — есть)          ├─ router_public.py  /api/v1/public/*
├─ enrich_geo.py, enrich_industry.py    ├─ router_my.py      /api/v1/pool-my/*
├─ antifraud.py (слои)                  ├─ router_admin.py   (есть, расширяем)
├─ referrals.py (этап 6)                └─ models.py (расширяем: согласия,
└─ geo/ справочники РФ (офлайн)            fingerprints, ip_log, сигналы…)
```

Идентификация гостя: **подписанная анонимная cookie** (`pool_vid`, секрет
ядра, 1 год) — чеки гостя копятся до регистрации; при регистрации история
**присоединяется** к аккаунту. Персональные данные — только по желанию.

## 3. Дорожная карта (этапы продолжают нумерацию плана v1)

### Этап 1 — v1.30.0 «Модель и приём через бота» — ✅ ВЫПОЛНЕН (2026-10-06)
Таблицы пула, пайплайн, баллы, оферта, админ-минимум. Канал «бот» — выполнен
и поставлен на паузу при смене концепции; вся база переиспользуется вебом.

### Этап 2 — v1.31.0 «Приём чеков на сайте» (≈1 неделя)
- Страница **#/public** (гостевая, из меню футера «Сдать чек»): вставка
  строки QR, **фото QR через jsQR** (камера/файл — сканер уже в проекте),
  ссылка вида `consumer.1-ofd.ru/…` (парсер извлекает t&s&fn&i&fp).
- Анонимная cookie `pool_vid`; чек-бокс **оферты** с записью факта согласия
  (`pool_consents`: user, version, ts, ip_hash).
- Антифрод-минимум сразу: honeypot-поле, тайминг заполнения формы,
  rate-limit на IP (nginx + существующий limiter), лимит 50 чек/сут.
- Ответ за ≤5 с: «чек принят, проверяю» + live-статус на странице.
- Критерий: чек с телефона попадает в пул с позициями; дубль отсечён;
  оферта зафиксирована; автотесты канала «web».

### Этап 3 — v1.32.0 «Кабинет и регистрация» (≈1–1,5 недели)
- Регистрация по плану: **email+пароль с подтверждением** и **magic link**
  (одноразовая ссылка на email); OAuth (Яндекс/VK) — опционально, флагом.
- Раздел **#/my**: баланс и «до ближайшей награды», история своих чеков со
  статусами, **экспорт своих чеков PDF/CSV** («сдал чек — забрал чек» из
  plan.md), профиль (email, пароль, удаление аккаунта со сгоранием баллов).
- **Слияние** анонимной истории (cookie) с аккаунтом при регистрации.
- Критерий: гость, сдавший 5 чеков, после регистрации видит их и баланс;
  экспорт своих чеков работает.

### Этап 4 — v1.33.0 «Гео и отрасли + панель модерации» (≈1 неделя)
- Справочники регионов/городов РФ (офлайн-JSON, `app/pool/geo/`);
  адрес места расчёта (ФФД 1.05+) → регион/город, `geo_accuracy`;
  fallback ИНН → Checko (ключ уже в Настройках) → юр. адрес.
- Справочник отраслей (дерево из plan.md) + словари сетей; чеку — отрасль,
  доминирующая по сумме позиций; позициям — нормализация имён.
- Панель **#/pool-admin**: очередь `pending` (одобрить/отклонить), поиск по
  ФН/ИНН/магазину, чеки без гео/отрасли, выгрузка CSV.
- Критерий: ≥70% новых чеков с регионом, ≥60% с отраслью; модерация в 2 клика.

### Этап 5 — v1.34.0 «Антифрод: 5 слоёв» (≈1,5 недели)
По разделам 3–5 plan.md, в нашем исполнении:
- **Слой 1 Device:** FingerprintJS (open source) → заголовок `X-Visitor-Id`,
  таблица `pool_fingerprints`; один visitor на 2+ аккаунтах → сигнал
  `MULTI_ACCOUNT_DEVICE` (+60).
- **Слой 2 Network:** `pool_ip_log` (ip, /24, UA), сигналы `SUBNET_CLUSTER`
  (5+ рег./сут с /24), `DATACENTER_IP` (+25), `VPN_OR_PROXY` (+15, не блок).
- **Слой 3 Behavior:** тайминги формы, honeypot, EXIF-эвристики фото
  (размер/метаданные), ровные интервалы чеков → `BOT_PATTERN` (+40),
  `RECEIPT_FLOOD` (+30).
- **Слой 4 Graph:** кластеры по visitor/подсети (SQL, рекурсивные CTE),
  `REFERRAL_FRAUD` (+50) при связи с рефералкой.
- **Слой 5 Rules:** таблица бизнес-правил (5+ одинаковых сумм подряд,
  20+ чеков/час и т.д.).
- `pool_risk`: risk_score 0–100, trust_level 0–3, **карантин вместо бана**,
  журнал `pool_signals` с разбором (new/reviewing/false_positive).
- Панель **#/fraud**: лента сигналов severity≥2, карточка участника
  (устройства, IP, связи), массовые действия, аннулирование баллов с записью.
- Критерий: сценарии «ферма аккаунтов», «взаимные рефералы», «накрутка
  чеками» отсекаются автотестами; ложных блокировок на честных нет.

### Этап 6 — v1.35.0 «Рефералы с порогами» (≈1 неделя)
Строго по разделу 2 plan.md (вторая часть):
- код `YM-XXXXXX`, ссылки `chek.ymaster.ru/r/КОД`; вкладка **#/my/invite**;
- бонусы **не за регистрацию, а за качественные действия с задержкой**:
  email подтверждён +5 (24 ч) · 1-й верифицированный чек ≥100 ₽ +20 (7 д) ·
  5-й +50 (14 д) · 20-й при trust≥1 +150 (30 д) · 50-й при trust≥2 +500 (60 д);
- lifetime-хвост 5% с потолком 200 балл/мес на реферала; **один уровень**;
  лимит 50 активных рефералов; антифрод-связка из Этапа 5
  (`SAME_SUBNET_REFERRAL`, `FAST_REFERRAL`, `REFERRAL_CYCLE`).
- Критерий: накрутка «сам себя пригласил» не приносит ни балла (автотесты).

### Этап 7 — v1.36.0 «Вовлечение» (≈1 неделя)
- Лидерборд (топ-10 по городу за месяц, публично и в кабинете), ачивки
  («50 чеков», «3 отрасли», «первый чек региона»), счётчик цели вывода,
  дайджест на email (опционально).
- Вывод баллов: заявка в кабинете; телефон — **только здесь** (хэш в БД),
  SMS-подтверждение первого вывода (шлюз подключим отдельным решением).

### Этап 8 — v1.37.0 «Подбор из пула для компаний» (≈1–1,5 недели)
- Раздел бухгалтера **«Подбор из пула»**: фильтры период/регион/отрасль/
  сумма/ИНН → привязка чеков к компании (`assigned_company_id`), выгрузка CSV.
- **Авто-подбор** под авансовый отчёт (набор чеков ≈ сумма ±5%).
- **Импорт «своих» сотрудников**: чек гостя с email/телефоном сотрудника
  компании уходит компании, а не в общий пул (сценарий C из plan.md).
- Квоты/тариф: счётчик подобранных (подписка 5 000 ₽/мес или 50 ₽/чек —
  решение при запуске), лимиты по тарифу, привязанный чек чужим не виден.
- Критерий: бухгалтер собирает отчёт из пула; ядро 1С/АО-1 не изменено.

### Этап 9+ — v1.38.0 и далее «Рост»
- ML-классификатор позиций (FastText) — когда корпус ≥5–10 тыс. позиций;
  граф-аналитика связей в панель #/fraud; партнёрские QR на кассах
  (кэшбэк-канал из plan.md); платное API для внешних клиентов.

## 5. 152-ФЗ и доверие (с Этапа 2, не позже)

- Храним только фискальные данные и анонимные ID; ФИО/телефон не собираем
  (телефон — только при выводе, хэшем).
- Оферта с чек-боксом и журналом согласий; отдельный пункт о технических
  данных (антифрод).
- Cookie-баннер с категориями (необходимые / антифрод / аналитика) —
  fingerprint включаем только после согласия на «антифрод».
- IP/fingerprint — хранение ≤12 месяцев, затем анонимизация.
- Пользователь вправе запросить свой risk_score (support@ymaster.ru).

## 6. Риски и митигации

| Риск | Митигация |
|---|---|
| Спам-боты на публичной форме | honeypot + тайминг + rate-limit IP + риск-скор (этапы 2, 5) |
| Квоты/баны источников при потоке | цепочка без квот (ФНС GetTicket → ЧЗ), «остывание», фоновая обработка |
| Накрутка рефералкой | пороги + задержки + граф-связи (этапы 5–6) |
| Нагрузка на БД | таблицы пула отдельно, аналитика фоном; Postgres в бою |
| 152-ФЗ | раздел 5 этого плана; согласия журналируются |
| Регрессия ядра | флаги выкл. по умолчанию, старые тесты не правим, бэкапы |

## 7. Метрики (с Этапа 2)

Конверсия страницы → первый чек; % повторных сдач; DAU сдающих; покрытие
регионов/городов; % с отраслью; % точного гео; доля чеков, взятых компаниями;
% отклонённых модерацией; доля отменённых антифродом бонусов (норма 10–20%).
Цели 6 месяцев (plan.md): 50 000 чеков, 40 регионов, 200 городов, 75%
размечено, 30% востребовано компаниями.

## 8. Что НЕ делаем (осознанно)

- Не возвращаем Telegram-канал без отдельного решения (код в проекте, пауза).
- Не встраиваем пул в таблицы ядра — только `assigned_company_id`.
- Не даём «бонус за регистрацию» и многоуровневую рефералку.
- Не продаём сами чеки.
- Не вводим Celery/Redis на старте — фоновых потоков FastAPI достаточно;
  ARQ — при росте (отдельное решение).
