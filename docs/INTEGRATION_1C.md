# 🟡 Интеграция «Ямастер Чек» ↔ 1С:Предприятие

> **Разработчик и владелец идеи: ООО «Ямастер»** · [ymaster.ru](https://ymaster.ru) · chek@ymaster.ru
> Поддерживаемые конфигурации: **1С:Бухгалтерия 3.0**, **1С:ERP 2**, **1С:УТ 11** (платформа 8.3.10+)

Два режима интеграции:

| Режим | Как работает | Когда выбирать |
|---|---|---|
| **Push (рекомендуется)** | Регламентное задание 1С само забирает новые чеки с сервера по HTTP и подтверждает загрузку | Постоянная автоматическая синхронизация |
| **Файловый экспорт** | Из веб-клиента скачивается пакет EnterpriseData (JSON/XML), загружается в 1С | Периодическая ручная передача, стартовое тестирование |

---

## 1. Подготовка на стороне сервера

1. Войдите как администратор → **Настройки → Интеграция с 1С**.
2. Нажмите **«показать»** и скопируйте **токен** (это значение заголовка `X-API-Token`).
3. Проверьте связь (из сети, где стоит 1С):

```bash
curl -H "X-API-Token: ВАШ_ТОКЕН" https://ваш-сервер/onec/v1/ping
# {"service":"Ямастер Чек","vendor":"ООО «Ямастер» (ymaster.ru)","pending_receipts":12,...}
```

При необходимости перевыпустите токен («♻ Сгенерировать») — старый перестанет работать.

### 1.1. Токен компании (с 1.70.92) — рекомендуется

Общий токен видит чеки **всех компаний** установки. Если в программе несколько компаний
(или вы аутсорсинговая бухгалтерия), выдайте базе 1С каждой компании свой токен:
**Выгрузка в 1С → Токены компаний → «Выпустить»**. Токен показывается один раз — сразу
сохраните его в настройках обмена базы 1С этой компании. С токеном компании:

- `/onec/v1/receipts/pull` и `/onec/v1/enterprise-data` отдают только чеки этой компании;
  чужой `company_id` — ответ 403;
- `/onec/v1/receipts/ack` отмечает выгруженными только её чеки;
- `/onec/v1/ping` отвечает `"scope": "company"` (общий токен — `"all"`).

Перевыпуск отзывает прежний токен, «Отозвать» — закрывает доступ. В базе хранится только
хеш токена. Общий токен продолжает работать как раньше.

## 2. Push-режим: настройка в 1С

### 2.1. Регистр дедупликации

В конфигураторе создайте **Регистр сведений** `ЯмастерЗагруженныеЧеки`:

| Объект | Имя | Тип | Длина |
|---|---|---|---|
| Измерение | ФН | Строка | 20 |
| Измерение | ФД | Строка | 10 |
| Измерение | ФП | Строка | 10 |
| Ресурс | ДокументСсылка | ДокументСсылка.ПоступлениеТоваровУслуг | — |
| Ресурс | ДатаЗагрузки | Дата | — |

По этому регистру 1С отсекает повторную загрузку одного и того же чека (ключ ФН+ФД+ФП).

### 2.2. Общий модуль

1. Создайте **общий модуль** `ЗагрузкаЧековЯмастер` (флаги: сервер ✓, вызов сервера ✓).
2. Скопируйте код из файла
   [integration_1c/РегламентноеЗадание_ЗагрузкаЧековЯмастер.bsl](../integration_1c/РегламентноеЗадание_ЗагрузкаЧековЯмастер.bsl).
3. Заполните три функции-настройки в начале модуля:

```bsl
Функция АдресСервера()
    Возврат "https://check.yourcompany.ru";  // адрес вашего сервера
КонецФункции

Функция ТокенAPI()
    Возврат "eyJ...";                        // токен из раздела «Настройки»
КонецФункции

Функция ДокументЦели()
    Возврат "ПоступлениеТоваровУслуг";       // или "АвансовыйОтчет"
КонецФункции
```

### 2.3. Регламентное задание

1. Конфигуратор → **Регламентные задания** → создать `ЗагрузкаЧековЯмастер`.
2. Метод: `ЗагрузкаЧековЯмастер.ВыполнитьЗагрузку`.
3. Расписание: каждые 10 минут.
4. Запустить в режиме предприятия → Администрирование → Регламентные задания → включить.

### 2.4. Что происходит при каждом запуске

```
1С ── GET /onec/v1/receipts/pull?limit=100&only_verified=true ──► Сервер Ямастер Чек
1С ◄── JSON: массив receipts (ФН, ФД, ФП, дата, сумма, позиции, extra по маппингу)
1С:  для каждого чека:  регистр говорит "уже загружен"? → пропустить
     иначе: создать и провести документ, записать в регистр
1С ── POST /onec/v1/receipts/ack {"ids":[...]} ──► Сервер: помечает чеки exported=true
```

Сервер больше не будет присылать подтверждённые чеки.

### 2.5. Формат `receipts` (Push v1)

```json
{
  "provider": "Ямастер Чек (ymaster.ru)",
  "format": "ymaster-push-v1",
  "target_object": "ПоступлениеТоваровУслуг",
  "count": 2,
  "has_more": false,
  "receipts": [
    {
      "id": "uuid-чека",
      "fn": "9999078902001234",
      "fd": "54321",
      "fp": "812345678",
      "date": "2025-09-01T14:30:00",
      "sum": 1520.50,
      "sum_kopecks": 152050,
      "operation": 1,
      "fns_status": "valid",
      "assignee": "Иванова Анна Петровна",
      "comment": "канцтовары для офиса",
      "qr": "t=20250901T1430&s=1520.50&fn=...&n=1",
      "items": [
        {"name": "Бумага А4", "qty": 2, "price": 549.00,
         "sum": 1098.00, "vat_rate": "20", "vat_sum": 183.00}
      ],
      "extra": {"СуммаДокумента": 152050, "Дата": "...", "ФН": "..."}
    }
  ]
}
```

Блок `extra` формируется **вашими правилами маппинга** из веб-клиента — в 1С можно
читать готовые реквизиты без пересчётов.

Поле **`assignee`** — сотрудник (подотчётник), назначенный чеку в веб-клиенте.
В EnterpriseData оно автоматически попадает в `КлючевыеСвойства.Контрагент.Наименование`
и в исходные поля `assignee`/`comment` — используйте их для авансовых отчётов:

```bsl
Док.Комментарий = "Ямастер: " + Чек.assignee + ", ФД " + Чек.ФД;
// Для АвансовогоОтчета: Док.ФизЛицо = НайтиИлиСоздатьФизЛицо(Чек.assignee);
```

## 3. Файловый экспорт (EnterpriseData)

1. Веб-клиент → **«Выгрузка в 1С»** → выберите документ и формат (JSON/XML) → скачайте файл.
2. В 1С загрузите пакет вашей обработкой импорта EnterpriseData. Структура объекта:

```json
{
  "ФорматВерсии": "1.3",
  "ИмяПакета": "ЯмастерЧек",
  "Данные": { "Контейнер": [
    {
      "ИмяПКО": "ПоступлениеТоваровУслуг",
      "КлючевыеСвойства": {
        "Ссылка": "ymaster-check-ab12cd34-...",
        "Номер": "54321",
        "Дата": "2025-09-01T14:30:00",
        "СуммаДокумента": 1520.50
      },
      "ФискальныеРеквизитыЧека": {
        "ФН": "...", "ФД": "...", "ФП": "...",
        "ПризнакРасчета": "Приход",
        "СтрокаЧекаQR": "t=...&n=1",
        "СтатусПроверкиФНС": "valid"
      },
      "ДополнительныеРеквизиты": { "...": "по вашему маппингу" },
```

## 3а. Первичка: УПД и счета-фактуры (с 1.70.96)

**Без программиста — файл УПД 5.03.** Веб-клиент → **«Первичка» → «⬇ В 1С» → «Файлы УПД для 1С»**.
В 1С:Бухгалтерии 3.0: **«Покупки → Поступление (акты, накладные, УПД) → Загрузить → Из файла»** —
так 1С загружает УПД в формате ФНС (например, из ЭДО Лайт) и предлагает сопоставить номенклатуру
([пример](https://infoblog.mywebguide.ru/articles/page_015330.html),
[форум Инфостарт](https://forum.infostart.ru/forum8/topic255630/)). Файл собирается из реквизитов
реестра, до выдачи проверяется по официальной XSD-схеме ФНС 5.03 (`app/primary/xsd/`); адресов нет,
подписант помечен «не указан» (`ДопСведПодп`). Имя файла постоянное:
`ON_NSCHFDOPPR_<ИНН покупателя>_<ИНН продавца>_<ГГГГММДД>_<id документа>.xml`.

**Для обмена без участия человека** — те же правила, что у чеков: заголовок `X-API-Token`, токен
компании видит только её документы (чужой `company_id` — 403), общий токен — все.

| Метод | Что делает |
|---|---|
| `GET /onec/v1/primary/pull?limit=100&include_errors=false` | новые (ещё не выгруженные) документы, формат `ymaster-primary-v1`; с ошибками проверки — только при `include_errors=true` |
| `POST /onec/v1/primary/ack` `{"ids": [...]}` | отметить загруженными — больше не отдаются |
| `GET /onec/v1/primary/enterprise-data?format=json\|xml&only_new=true` | пакет EnterpriseData: `ПоступлениеТоваровУслуг` (УПД, ДОП) и `СчетФактураПолученный` (СЧФ, СЧФДОП) |
| `GET /onec/v1/primary/{id}/upd` | файл УПД 5.03 документа (422 с причиной, если файл честно не собрать) |
| `GET /onec/v1/ping` | в ответе — `pending_primary`: сколько документов ждут выгрузки |

Документ в `pull`:

```json
{"id": "…", "kind": "УПД", "function": "СЧФДОП", "number": "УТ-15", "date": "2026-03-10",
 "seller": {"name": "ООО «СтройБаза»", "inn": "5001007329", "kpp": "500101001"},
 "buyer": {"name": "…", "inn": "…", "kpp": "…"}, "currency": "643", "status": "ok", "source": "xml",
 "totals": {"without_vat": 6500.0, "vat": 1430.0, "with_vat": 7930.0},
 "upd_file": "ON_NSCHFDOPPR_…xml",
 "lines": [{"position": 1, "name": "Цемент М500", "unit_code": "796", "qty": 10, "price": 500.0,
            "sum_without_vat": 5000.0, "vat_rate": "22", "vat_1c": "НДС22", "vat_sum": 1100.0,
            "sum_with_vat": 6100.0, "item_code": "CEM-500"}]}
```

В EnterpriseData ключ объекта — `ymaster-primary-<id>` (счёт-фактура — с `-sf`), у счёта-фактуры к УПД —
`ДокументОснование` со ссылкой на поступление. Расширение 1С с HTTP-сервисом и квитированием — T-52
(нужна тестовая база 1С).

## 4. Маппинг реквизитов

Веб-клиент → **«Маппинг»**. Правила определяют содержимое `ДополнительныеРеквизиты`
и `extra`. Примеры:

| Поле чека | Реквизит 1С | Преобразование | Результат |
|---|---|---|---|
| total_sum | СуммаДокумента | kopecks | 1520.50 → `152050` |
| receipt_date | Дата | date_iso | `2025-09-01T14:30:00` |
| operation | ВидОперации | operation_sign | `Приход` / `ВозвратПрихода` |
| fn | ФН | direct | как есть |
| qr_data | Комментарий | direct | строка QR целиком |
| (константа) | Подразделение | constant | `Розница-1` |

## 5. Особенности конфигураций

| Конфигурация | Документ | Нюансы |
|---|---|---|
| **БП 3.0** | Поступление (акты, накладные) | Обязательны: контрагент, договор, счёт учёта НДС. Заполняйте в своей процедуре при создании документа. |
| **БП 3.0** | Авансовый отчёт | Реквизит «Физическое лицо» — подотчётник; чеки удобно класть в таблицу «Товары». |
| **ERP 2 / УТ 11** | Поступление товаров и услуг | Имена реквизитов могут отличаться (`СуммаВзаиморасчетов` и т.п.) — используйте `extra` по маппингу. |

> Ключевое: сумма и фискальные реквизиты приходят готовыми, а реквизиты организации
> (контрагент/склад/подразделение) задаются в вашей обработке — типовая практика для
> внешних источников чеков.

## 6. Диагностика

| Проблема | Проверить |
|---|---|
| `401 Неверный X-API-Token` | Токен в модуле 1С = токен в настройках; нет лишних пробелов |
| Таймауты HTTPS | Сертификат сервера в доверенных узлов 1С: Администрирование → Интернет-поддержка → Сертификаты |
| Чеки не приходят | Фильтр `only_verified=true` — чек ещё не проверен в ФНС; запустите проверку в веб-клиенте |
| Чеки приходят повторно | Не вызывается `/ack` или не заполняется регистр дедупликации |
| Ошибка создания документа | Журнал регистрации 1С: `Ямастер.ЗагрузкаЧеков` — там текст исключения |

Журнал обращений 1С к серверу виден в веб-клиенте: **Журнал** → события `onec_pull`, `onec_ack`.
