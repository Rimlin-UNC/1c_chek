## Как это работает

После сканирования чека (строка QR: t=…&s=…&fn=…&i=…&fp=…&n=…) система
может автоматически запросить у внешних источников ПОЛНУЮ расшифровку:

    Магазин (наименование, ИНН, адрес места расчёта)
    Кассир/оператор
    Сумма, наличные/безналичные
    ВСЕ ПОЗИЦИИ чека: наименование, количество, цена, сумма, НДС

Данные записываются в карточку чека, попадают в CSV и в выгрузку в 1С.
Включается настройкой «Автоматически получать данные после сканирования»
(Настройки → Источники данных чека; по умолчанию включено).

## Доступные источники

| Источник        | Что даёт                                   | Что нужно                                      |
|-----------------|--------------------------------------------|------------------------------------------------|
| fns_api         | Официальная проверка ФНС (реквизиты)       | Мастер-токен ФНС (заявление, см. ниже)         |
| proverkacheka   | proverkacheka.com — полный чек с позициями | Токен из личного кабинета (бесплатно)          |
| custom          | Любой ваш сервис (напр. проверкачека.рф)   | URL, поддерживающий контракт (см. ниже)        |
| mock            | Демо-режим (для тестов)                    | ничего                                         |

### 1. proverkacheka.com (рекомендуемый бесплатный старт)
1. Зарегистрируйтесь на https://proverkacheka.com/ (личный кабинет бесплатен).
2. Кабинет → раздел «Справка» → сгенерировать ключ-токен API.
3. Вставьте токен: Настройки → «Источники данных чека» → «Токен proverkacheka.com» → Сохранить.
4. Нажмите «🧪 Тест контрольным чеком» — система запросит тестовый чек и покажет результат.

Запрос система выполняет так (официальное API сервиса):
    POST https://proverkacheka.com/api/v1/check/get
    данные формы: qrraw=<строка QR>, token=<ваш токен>

### 2. Официальное API ФНС «Открытое API проверки чека ККТ»
Доступ выдаёт ФНС по заявлению (юридическое лицо, ЭП, описание сценария
использования). Когда получите Мастер-токен:
    Настройки → «Проверка чеков (ФНС)» → провайдер «Реальное API ФНС»
    → вставьте Мастер-токен → Сохранить.
Технические условия и схема подключения описаны в docs/knowledge/fns_auth.md
(SOAP AuthService/0.1 → временный токен на 6 часов → POST /api/2/check).
Система сама кэширует проверки (по умолчанию 7 дней) — лимиты не расходуются.

### 3. Свой источник (проверкачека.рф и другие)
У проверкачека.рф сейчас нет публичного API (проверка через их сайт/приложение).
Как только появится — укажите его URL в поле «Свой источник». Контракт:

    POST <ваш URL>
    тело JSON:  {"qrraw": "t=…&s=…&fn=…&i=…&fp=…&n=1"}
    ответ JSON: {"document": {"receipt": {...}}}   — как у ФНС/proverkacheka,
                либо любой JSON, где есть items + totalSum
    суммы — в копейках (система сама определяет масштаб по сумме из QR).

## Защита от блокировок (встроена, работает всегда)

  1. ПОСЛЕДОВАТЕЛЬНОСТЬ — все внешние запросы идут строго по одному
     (общая очередь, даже если сканируют несколько сотрудников).
  2. ПАУЗА 2–7 СЕКУНД — перед каждым запросом случайная пауза
     (короткие серии «как робот» невозможны по построению).
  3. РОТАЦИЯ — источники опрашиваются по порядку; если один недоступен,
     автоматически используется следующий.
  4. «ОСТЫВАНИЕ» — получив 429/403 (лимит/блокировка), источник выключается
     на 10 → 20 → 40 … минут (до 6 часов) и не беспокоится.
  5. КЭШ — проверенный чек не запрашивается повторно 7 дней.
  6. Таймаут запроса — 20 секунд; зависший сервис не тормозит очередь.

Состояние источников в реальном времени:
    Настройки → «Источники данных чека» → «🧪 Тест»
    или GET /api/v1/receipts/external/status (бухгалтер+)

## Формы в интерфейсе

| Где                    | Что появилось в v1.2.0                                          |
|------------------------|-----------------------------------------------------------------|
| Чеки (таблица)         | кнопка 📥 у каждого чека — получить данные; кнопка ✏️ — редактор |
| Чеки (панель бухгалтера)| «📥 Данные сервисов» — массовое получение для выбранных чеков    |
| Редактор чека          | дата, сумма, тип, ФН/ФД/ФП, магазин, ИНН, адрес, кассир, сотрудник, позиции (добавление/удаление) |
| Чек сотрудника         | 🔔 «Уведомить бухгалтерию» + комментарий (только свои чеки)      |
| Настройки → Источники  | токены, свой URL, порядок источников, авто-режим, тест           |

## Правила изменения данных (роли)

| Действие                          | Сотрудник | Бухгалтер | Администратор |
|-----------------------------------|-----------|-----------|---------------|
| Уведомление 🔔 + комментарий      | свой чек  | любой     | любой         |
| Сотрудник (подотчётник)           | нельзя    | да        | да            |
| Магазин/ИНН/адрес/кассир          | нельзя    | да        | да            |
| Дата, сумма, тип, ФН/ФД/ФП, позиции | нельзя  | да (не выгруженные) | да (включая выгруженные) |

Чек от сотрудника СРАЗУ помечается «от кого прислал» — вручную назначать
не нужно; при желании бухгалтер перевазначит за один клик.
