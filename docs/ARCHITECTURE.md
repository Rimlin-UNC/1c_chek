## ADR-01

**Решение.** Стек: FastAPI + SQLAlchemy 2 + SQLite (WAL) или PostgreSQL 17, vanilla JS SPA + PWA без сборки фронтенда.

- **Статус:** принято; **с версии / даты:** исходное ТЗ
- **Контекст и причина:** Один сервер, простое развёртывание (Docker, systemd, Nginx); SQLite в режиме WAL с busy_timeout для параллельных чтений
- **Последствия:** Рабочая БД — файл data/ymaster_check.db; фоновые задачи в процессе приложения; без бандлера
- **Источник:** [README.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/README.md)

## ADR-02

**Решение.** Без Celery/Redis: фоновые задачи — потоки внутри приложения.

- **Статус:** принято; **с версии / даты:** стандарт выпуска
- **Контекст и причина:** Требование стандарта выпуска; ограниченные ресурсы сервера
- **Последствия:** Очереди и воркеры живут в процессе; serverless-платформы не подходят без доработок
- **Источник:** [docs/update_playbook.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/update_playbook.md)
- **Задачи:** T-10

## ADR-03

**Решение.** Миграции только добавляющие, без Alembic: create_all + _ensure_schema в init_db.

- **Статус:** принято; **с версии / даты:** стандарт выпуска
- **Контекст и причина:** Откат кода без отката базы: старая версия должна работать с новой схемой
- **Последствия:** Нельзя удалять и переименовывать колонки и таблицы; данные чинятся идемпотентными шагами при старте
- **Источник:** [docs/update_playbook.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/update_playbook.md)
- **Задачи:** T-07

## ADR-04

**Решение.** Обновление из программы: только вперёд по версии; ветка-источник; бэкап → fetch → reset → pip при изменении requirements → проверка целостности → перезапуск (re-exec); откат к «последней рабочей версии».

- **Статус:** принято; **с версии / даты:** v1.6.0 / v1.17.0 / v1.46.0
- **Контекст и причина:** Владелец обновляет сервер сам, без SSH; при сбое — автоматический откат кода
- **Последствия:** Каждый выпуск обязан обновлять версию; изменения БД должны переживать откат кода
- **Источник:** [app/services/updater.py](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/app/services/updater.py)
- **Задачи:** T-01, T-03, T-13

## ADR-05

**Решение.** Блок «Проверка чеков (ФНС и источники)» не менять без указания владельца; пауза антибана 2–7 с и квота proverkacheka (12–14/сутки) критичны.

- **Статус:** принято; **с версии / даты:** стандарт выпуска
- **Контекст и причина:** Квота ФНС ограничена и дорога; риск блокировки
- **Последствия:** Изменения рядом с ФНС — только в обвязке и с тестами
- **Источник:** [docs/update_playbook.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/update_playbook.md)

## ADR-06

**Решение.** Единый фискальный документ: один чек = одна запись (identity_key = sha256 от ФН, ФД и ФП); старые таблицы receipts и pool_receipts остаются проекциями; живые операции строгие (409), перенос архива — с карантином конфликтов.

- **Статус:** принято; **с версии / даты:** v1.70.81–v1.70.82
- **Контекст и причина:** Убрать второй смысл чека и вторую строку владения, не ломая 1С, баллы и историю
- **Последствия:** Неполные тройки не склеиваются; таблицы unified_* создаются пустыми; перенос архива — отдельная команда
- **Источник:** [docs/unified_receipts.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/unified_receipts.md)
- **Задачи:** T-06, T-07

## ADR-07

**Решение.** Синхронизация ответа ФНС и внешних данных с единым реестром — без потерь (SAVEPOINT).

- **Статус:** принято; **с версии / даты:** v1.70.82
- **Контекст и причина:** Ответ ФНС оплачен квотой и важнее канонической копии
- **Последствия:** Сбой единого реестра откатывает только синхронизацию; причина пишется в журнал
- **Источник:** [app/unified/service.py](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/app/unified/service.py)

## ADR-08

**Решение.** Видимость: экраны реестра и пула — штатные фильтры компании и автора плюс скрытие чеков со спорной принадлежностью; единый API для штатных ролей требует согласия живых копий.

- **Статус:** принято; **с версии / даты:** v1.70.82
- **Контекст и причина:** Расхождение после отката на старую версию не должно прятать чек у своей компании или показывать его чужой
- **Последствия:** Карантин ставит только перенос архива; живые операции отказывают (409)
- **Источник:** [docs/rbac_matrix.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/rbac_matrix.md)
- **Задачи:** T-06

## ADR-09

**Решение.** unified_ownership без внешних ключей на companies/users; сверка канона с рабочими таблицами при каждом старте (app.unified.reconcile).

- **Статус:** принято; **с версии / даты:** v1.70.82
- **Контекст и причина:** Старая версия после отката удаляет компании; FK ломал это (проверено репетицией)
- **Последствия:** Целостность держат сервис и сверка; исправления пишутся событием reconcile
- **Источник:** [app/unified/reconcile.py](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/app/unified/reconcile.py)

## ADR-10

**Решение.** Supabase — отдельный read-only демо-контур с синтетическими данными; не рабочая DATABASE_URL; таблицы под принудительным RLS, чтение через представления и RPC; регистрация в Auth отключена.

- **Статус:** принято; **с версии / даты:** v1.70.81
- **Контекст и причина:** Показать модель данных наглядно, не трогая рабочую базу и персональные данные
- **Последствия:** В браузер — только publishable key; данные приложения в Supabase не переносились
- **Источник:** [supabase/README.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/supabase/README.md)
- **Задачи:** T-04, T-05, T-11

## ADR-11

- **Статус:** принято; **с версии / даты:** v1.70.61
- **Контекст и причина:** Единые права на сервере и в интерфейсе
- **Последствия:** Новый экран добавляется в обе матрицы
- **Источник:** [docs/rbac_matrix.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/rbac_matrix.md)

## ADR-12

**Решение.** 152-ФЗ: персональные данные не покидают базу; обезличенные коды участников; журналы без фискальных значений и ПДн.

- **Статус:** принято; **с версии / даты:** стандарт выпуска
- **Контекст и причина:** Требование законодательства и стандарта выпуска
- **Последствия:** Нельзя выгружать ПДн во внешние сервисы (включая Supabase/Notion)
- **Источник:** [docs/update_playbook.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/update_playbook.md)

## ADR-15

**Решение.** Стандарт выпуска: версия синхронно в 7 местах, CHANGELOG, WHATS_NEW, журнал UI; выпуск только при 0 failed; прогон тестов не прерывать; коммит «vX.Y.Z: суть; NNN passed».

- **Статус:** принято; **с версии / даты:** стандарт выпуска
- **Контекст и причина:** Обновление из программы читает версию и CHANGELOG из ветки
- **Последствия:** Тесты релиза проверяют все точки синхронизации
- **Источник:** [docs/update_playbook.md](https://github.com/Rimlin-UNC/1c_chek/blob/cd769234ebfc4d5c533a1df25fce31e8a9605212/docs/update_playbook.md)

## ADR-16

**Решение.** База знаний и рабочий процесс — в GitHub: docs/kb (Markdown + CSV), AGENTS.md, CI, шаблоны PR и задач; Notion не используется; для владельца — презентация в Google Slides.

- **Статус:** принято; **с версии / даты:** 2026-11-02
- **Контекст и причина:** Коннектор Notion не мог создать страницы без подключённой родительской страницы; владелец убрал Notion из коннекторов и поручил вести работу в GitHub и доступных коннекторах
- **Последствия:** Источник истины — репозиторий; презентация обновляется в конце сессии по базе знаний; T-14 отменена, Q-12 закрыт
- **Источник:** [PR #3](https://github.com/Rimlin-UNC/1c_chek/pull/3)
- **Задачи:** T-14, T-21

## ADR-17

**Решение.** CI: GitHub Actions на каждый push в main и arena/** — ./test.sh full на Python 3.11 и 3.12 с PostgreSQL 17 и всей цепочкой инструментов; ворота qa/junit_gate.py — 0 упавших и 0 пропущенных; тесты не зависят от машины.

- **Статус:** принято; **с версии / даты:** 2026-11-02
- **Контекст и причина:** Пропуски зависели от окружения (14, 10, 1), тесты PostgreSQL не гонялись регулярно; первый прогон CI нашёл 2 теста, зависевших от версии systemd
- **Последствия:** Пропуск в CI — провал; детали падений — аннотациями (видны в PR и через API аннотаций); 3.12 — как на Ubuntu 24.04 рабочего сервера
- **Источник:** [.github/workflows/ci.yml](https://github.com/Rimlin-UNC/1c_chek/blob/820bf7c9df7008aeacca88b1955a5ba8dca8fea2/.github/workflows/ci.yml)
- **Задачи:** T-09

## ADR-18

**Решение.** Файлы supabase/migrations побайтно совпадают с применённой историей проекта (имя файла = версия); историю в Supabase не переписываем; проверка — verify.sql в CI на чистом PostgreSQL 17.

- **Статус:** принято; **с версии / даты:** 2026-11-02
- **Контекст и причина:** Файлы 2026110101–03 расходились с историей: другие версии, иное разбиение схемы и данных, комментарии
- **Последствия:** Новая миграция — файл с версией, затем применение; повторный запуск файла должен пройти или откатиться целиком
- **Источник:** [supabase/README.md](https://github.com/Rimlin-UNC/1c_chek/blob/820bf7c9df7008aeacca88b1955a5ba8dca8fea2/supabase/README.md)
- **Задачи:** T-05

## ADR-19

**Решение.** GitHub — единственный источник истины. Канонические документы — docs/OVERVIEW.md, docs/ARCHITECTURE.md, docs/RUNBOOK.md, docs/DATABASE.md и AGENTS.md; живые базы — docs/kb (задачи, вопросы, журнал в CSV); Google Sheets, Docs и Slides — только представления и отчёты, построенные из репозитория.

- **Статус:** принято; **с версии / даты:** 2026-11-02
- **Контекст и причина:** Указание владельца: GitHub — единственный источник истины, Google Sheets и Docs — вспомогательные инструменты для тестирования, отчётности и визуализации. Документы базы знаний дублировали бы новые файлы docs/*.md, поэтому объединены
- **Последствия:** Правки — только в GitHub; QA-матрица генерируется qa/test_matrix.py и загружается в Sheets, канбан импортирует docs/kb/02_roadmap.csv; статус в CI подтверждается отпечатком набора тестов; доска GitHub Projects токену недоступна (403) — канбан в Sheets; ADR-16 уточнено: страницы docs/kb 01, 03, 04, 05, 07 стали ссылками
- **Источник:** [PR #3](https://github.com/Rimlin-UNC/1c_chek/pull/3)
- **Задачи:** T-23, T-26, T-27, T-28

## Как добавлять решение

1. Решение принимается в задаче (issue или PR); владелец подтверждает решения,
   которые затрагивают продукт, рабочий сервер или данные.
2. Новый раздел `ADR-NN` в этом файле и строка в перечне: статус, причина по
   источнику, последствия, ссылка на PR или документ.
3. Если решение отменяет прежнее — старому ставится `заменено` со ссылкой на
   новое. Разделы не удаляются.
