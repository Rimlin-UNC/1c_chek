# 9. Реестр выпусков: история и откат

[← База знаний](README.md) · База: [`09_releases.csv`](09_releases.csv) ·
Связанные разделы: [Задачи](02_roadmap.md) · [Журнал сессий](08_session_journal.md) ·
[Стандарт выпуска](../update_playbook.md)

Канонический список — **`09_releases.csv`**: одна строка на выпуск — версия, дата,
коммит, суть, число тестов и прогон CI, репетиция обновления, этап Б (обновление из
программы с GitHub), опора репетиции и можно ли на него откатываться. Ссылки —
на коммит, прогон CI или PR. Данных нет — «требует уточнения», не выдумывать.

## Как пользоваться

- **Вспомнить, что где:** номер версии → коммит → прогон CI и проверки. Подробности
  выпуска — в [CHANGELOG](../../CHANGELOG.md) и в разделе PR
  [#3](https://github.com/Rimlin-UNC/1c_chek/pull/3).
- **Опора репетиции** — версии, с которых проверяется обновление на текущую:
  `qa/release_gate.py` берёт их отсюда (колонка «Опора репетиции» = «да»):
  ```bash
  .venv/bin/python -m qa.release_gate refs          # список опор и есть ли коммиты локально
  .venv/bin/python -m qa.release_gate rehearsal     # репетиция от всех опор подряд
  .venv/bin/python -m qa.release_gate stage-b       # этап Б — после push выпуска
  .venv/bin/python -m qa.release_gate ci            # ждать CI ветки и напечатать итог ворот
  ```

## Откат

| Что откатить | Кто и как |
|---|---|
| Программа на рабочем сервере | Владелец: «🔄 Обновления» → «↩ Последние рабочие версии» → «↩ Откатиться» у нужной версии. Перед каждым обновлением программа сама делает резервную копию базы. Колонка «Откат на неё» подсказывает, на какие версии откатываться не стоит |
| Код в ветке | Агент: `git revert <коммит>` новым коммитом и push в ветку сессии. Историю не переписывать: без `push --force` и `reset --hard` |
| Документы и базы `docs/kb` | Тем же `git revert` или правкой с записью в журнале; удалять записи без причины нельзя |
| Данные рабочей базы | Только владелец, из резервной копии на сервере (ADR-14: рабочая база сюда не переносится) |

## Правило пополнения

Строка выпуска добавляется в коммите выпуска (колонки «Прогон CI» и «Этап Б» —
«после публикации») и уточняется в коммите базы знаний после CI и этапа Б.
Номер версии растёт; строки не удаляются.
