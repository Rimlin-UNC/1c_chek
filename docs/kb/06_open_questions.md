## Вопросы к владельцу

- **Q-02.** Какая ветка стоит в «Источнике обновлений» на рабочем сервере и
  установлена ли одна из v1.70.82–v1.70.85? Последний отчёт: v1.70.80, `b3db4fe`, 01.11.2026.
- **Q-03.** Роль Vercel: production из `main` (v1.70.15), работоспособность в
  serverless не проверена.
- **Q-04.** Закрыть PR #2 как полностью вошедший в PR #3?
- **Q-05.** Сливать ли PR #3 в `main`? Это запустит production-деплой Vercel,
  а `main` — ветка обновлений по умолчанию.
- **Q-06.** Нужен ли переход рабочей БД на PostgreSQL/Supabase: хостинг,
  размещение ПДн (152-ФЗ), окно простоя, откат?
- **Q-10.** `public.rls_auto_enable()` и триггер `ensure_rls` не из миграций
  проекта; EXECUTE у PUBLIC. Обзор 02.11: функция событийного триггера, напрямую
  не вызывается — риск низкий. Происхождение (настройка в Dashboard?) —
  требует уточнения → T-22, [#18](https://github.com/Rimlin-UNC/1c_chek/issues/18).
- **Q-11.** Какие схемы открыты PostgREST (exposed schemas)? Проверить в
  Dashboard → API → T-22, [#18](https://github.com/Rimlin-UNC/1c_chek/issues/18).
- **Q-16.** Интеграция Supabase ↔ GitHub: включено ли автоприменение и куда её
  привязать? → **Ответ получен (02.11.2026):** автоприменение есть — push в
  production-ветку разворачивает `supabase/` в рабочий проект. Владелец
  переключил интеграцию с ветки PR #2 на ветку PR #3; после слияния PR #3 —
  переключить на `main` → T-25, [#21](https://github.com/Rimlin-UNC/1c_chek/issues/21).
- **Q-15.** Представления `public.chek_demo_*` выполняются с правами владельца
  (без `security_invoker`) и обходят RLS базовых таблиц. Оставить как осознанное
  исключение для синтетики или перевести на `security_invoker` + политики RLS?
  → T-22, [#18](https://github.com/Rimlin-UNC/1c_chek/issues/18).
- **Q-14.** Параметры рабочего сервера (домен, ветка, версия, Docker или systemd)
  агенту недоступны.
- **Q-18…Q-23.** Единая база ([#24](https://github.com/Rimlin-UNC/1c_chek/issues/24),
  [проект](../single_base_design.md), ADR-20) → **Ответ получен (02.11.2026): «Да, по
  рекомендациям»**:
  - модель — один владелец и заявки;
  - прежние владельцы в число организаций не входят, администратор видит их в списке;
  - показ числа компаниям по умолчанию выключен, включается выбранным компаниям флагом;
  - число видят бухгалтер и руководитель;
  - сотруднику при отказе — «заявка передана администратору»;
  - начать с фазы 0 — выпущено в 1.70.84 (Q-23 закрыт). Q-18…Q-22 — `answered`: Q-18, Q-19 и Q-22
    выполнены в 1.70.85 (фазы 1–2, T-34), Q-20 и Q-21 — в фазе 3 (T-35).

  Рекомендации — в проекте, п. 8 → T-32…T-35.
- **Q-24.** Пакетное перемещение: если среди отмеченных есть чек, который ждёт
  разбора, — отклонять всю пачку, как сейчас (ответ 409, ничего не переносится), или

  → T-33, [#24](https://github.com/Rimlin-UNC/1c_chek/issues/24).
