## 2. Проверено — уязвимостей НЕ найдено

- **JWT**: алгоритм зафиксирован (HS256), `alg=none` отклонён, подделка чужим
  ключом → 401, истёкший → 401; пароли PBKDF2-SHA256, 260k итераций.
- **Роли и изоляция**: сотрудник не читает настройки ботов/пула/системы (403),
  не запускает verify; чужая компания не видит и не может удалить чек (404);
  компания-скоуп соблюдён в списке и карточке.
- **1С-интеграция**: без токена и с неверным → 401; сравнение
  `hmac.compare_digest` (защита от timing-атак).
- **Куки-аутентификация**: HttpOnly + SameSite=Lax; CSP `default-src 'self'`,
  `object-src 'none'`, `frame-ancestors 'none'`, `geolocation=()` — геолокация
  запрещена даже на уровне браузера (152-ФЗ).
- **Секреты**: `onec_api_token`, `max_bot_token`, `webhook_secret`,
  `telegram_bot_token`, `ofd_ru_token` — шифруются (AES-CBC+HMAC); в ответах
  API только маски.
- **Ввод**: гигантский username → 422; `page_size=5000` → 422; битый PNG →
  честная 422; `page`/`page_size` с границами; ORM везде (инъекций не найдено);
  опасных вызовов (`eval`, `pickle`, `shell=True`) нет; `ast.literal_eval`
  только на собственном конфиге блоков.
- **Приглашения**: токен `secrets.token_urlsafe(16)` (~128 бит).
- **Rate-limit**: при честных IP держит (240/мин api, логин-гард после 5
  неудач).

## 4. Рекомендации (по приоритету, не срочно)

1. **Прод**: после деплоя проверить в журнале отсутствие варнинга
   «SECRET_KEY …» (`sudo journalctl -u ymaster-check | grep SECRET_KEY`).
   Ключ генерируется установщиком — проверка формальная, но важная.
2. **v1.68+ (по спросу): очередь-воркер для автозагрузки деталей** —
   2 демона-воркера вместо background-задач снимет последние пики
   (как сделано в webhooks v1.67.0). Не делать раньше спроса.
3. **XFF в проде**: убедиться, что nginx ставит `X-Forwarded-For $remote_addr`
   (не добавляет к клиентскому). Иначе доверие к loopback-прокси вернёт
   обход лимитов. Однострочная проверка конфига.
4. **Токен в localStorage**: дублируется в HttpOnly-куке (это хорошо);
   долгосрочно — убрать из localStorage совсем, читать куку. Низкий
   приоритет: CSP жёсткий, XSS-векторов не найдено.
5. **Бэкапы**: неделя копий на внешнем носителе уже настроена — раз в
   квартал тренировать восстановление (сценарий «упавшая база»).
6. **Мониторинг**: раз в сутки следить за «В очереди: N ждёт» вебхуков в
   настройках — рост очереди = приёмник недоступен.
