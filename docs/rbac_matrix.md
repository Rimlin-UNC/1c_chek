# Иерархия ролей и пространства доступа (v1.70.61)

Источник истины: `app/services/rbac.py` (сервер) и `ROLE_SPACE` в
`app/static/js/app.js` (клиент). Замок выпуска `tests/test_v17061.py`
сверяет оба источника по ключам, чтобы пространство не разъехалось.
Сервер отдаёт пространство роли в `GET /api/v1/me` → ключ `space`
(`role`, `level`, `views`, `settings`).

## Ветка иерархии уровней

```
5  АДМИНИСТРАТОР (admin)
   │   всё пространство программы: данные, компании, пользователи,
   │   журнал, антифрод, пул-админ, B2B, мониторинг, все настройки
4  ├── БУХГАЛТЕР (accountant)
   │     чеки и выгрузка: сканирование, реестр чеков, выгрузка в 1С,
   │     мапинг реквизитов, подбор чеков из пула;
   │     настройки: проверка чеков и почта + личное
3  ├── РУКОВОДИТЕЛЬ (manager) — только просмотр
   │     сводки дашборда, реестр чеков (чтение), свой отчёт;
   │     настройки: только личное
2  ├── СОТРУДНИК (user)
   │     рабочая зона: сканирование, реестр чеков компании, сводки;
   │     настройки: только личное
1  └── УЧАСТНИК-ДОНОР (donor) — упрощённое пространство пула
        сдать чек (public), свои бонусы и баланс (my),
        партнёры и рефералы (partners); настроек нет вовсе
0      ГОСТЬ (guest) — та же ветка пула без кабинета
```

Пространства ролей компании вложены в пространство администратора по
экранам; пространство донора **не пересекается** с контуром компании:
донор не видит ни дашборда, ни чеков компании, ни настроек, ни меню
сверх трёх пунктов пула (`hierarchy_is_intact()`).

## Где применяется

- **Меню**: `enterApp()` скрывает пункт, если экрана нет в пространстве
  роли (поверх классовых фильтров `admin-only` и пр. и пул-логики
  v1.58.1 — они остаются страховкой).
- **Маршруты**: `route()` не открывает раздел вне пространства даже
  прямой ссылкой: компания уходит на дашборд, гость — на сдачу чека.
- **Настройки**: меню настроек строится только из групп роли, карточки
  `data-sec` вне разделов роли скрыты.
- **Сервер**: прежние зависимости `require_admin` / `require_role`
  продолжают охранять API; токен пула (`typ=pool`) ядром не принимается,
  токен ядра — пулом. Пространство в `/me` — справочное для клиента и
  интеграций, поведение сервера от него не зависит.

## Проверка

`tests/test_v17061.py`: иерархия и непересечение донора, паритет
сервер/клиент по ключам, охрана меню/маршрутов/настроек в исходнике,
`space` в payload `/me`. Роли в живом прогоне: администратор видит всё,
сотрудник — рабочую зону, донор — три пункта пула.
