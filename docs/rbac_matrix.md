# Иерархия ролей и пространства доступа (v1.70.61)

Источник истины: `app/services/rbac.py` (сервер) и `ROLE_SPACE` в
`app/static/js/app.js` (клиент). Замок выпуска `tests/test_v17061.py`
сверяет оба источника по ключам, чтобы пространство не разъехалось.
Сервер отдаёт пространство роли в `GET /api/v1/me` → ключ `space`
(`role`, `level`, `views`, `settings`).

## Ветка иерархии уровней

```
5  АДМИНИСТРАТОР (admin)
   │   всё пространство программы: данные, компании, пользователи,
   │   журнал, антифрод, пул-админ, B2B, мониторинг, все настройки
4  ├── БУХГАЛТЕР (accountant)
   │     чеки и выгрузка: сканирование, реестр чеков, выгрузка в 1С,
   │     мапинг реквизитов, подбор чеков из пула;
   │     настройки: проверка чеков и почта + личное
3  ├── РУКОВОДИТЕЛЬ (manager) — только просмотр
   │     сводки дашборда, реестр чеков (чтение), свой отчёт;
   │     настройки: только личное
2  ├── СОТРУДНИК (user)
   │     рабочая зона: сканирование, реестр чеков компании, сводки;
   │     настройки: только личное
1  └── УЧАСТНИК-ДОНОР (donor) — упрощённое пространство пула
        сдать чек (public), свои бонусы и баланс (my),
        партнёры и рефералы (partners); настроек нет вовсе
0      ГОСТЬ (guest) — та же ветка пула без кабинета
```

Пространства ролей компании вложены в пространство администратора по
экранам; пространство донора **не пересекается** с контуром компании:
донор не видит ни дашборда, ни чеков компании, ни настроек, ни меню
сверх трёх пунктов пула (`hierarchy_is_intact()`).

## Где применяется

- **Меню**: `enterApp()` скрывает пункт, если экрана нет в пространстве
  роли (поверх классовых фильтров `admin-only` и пр. и пул-логики
  v1.58.1 — они остаются страховкой).
- **Маршруты**: `route()` не открывает раздел вне пространства даже
  прямой ссылкой: компания уходит на дашборд, гость — на сдачу чека.
- **Настройки**: меню настроек строится только из групп роли, карточки
  `data-sec` вне разделов роли скрыты.
- **Сервер**: прежние зависимости `require_admin` / `require_role`
  продолжают охранять API; токен пула (`typ=pool`) ядром не принимается,
  токен ядра — пулом. Пространство в `/me` — справочное для клиента и
  интеграций, поведение сервера от него не зависит.

## Проверка

`tests/test_v17061.py`: иерархия и непересечение донора, паритет
сервер/клиент по ключам, охрана меню/маршрутов/настроек в исходнике,
`space` в payload `/me`. Роли в живом прогоне: администратор видит всё,
сотрудник — рабочую зону, донор — три пункта пула.

## Единый фискальный документ (`/api/v1/unified`)

Канонический слой не расширяет пространство роли: он использует те же
проверки компании и автора, что и реестр чеков. С 1.70.82 штатной роли
документ виден, только если живые копии чека (реестр и пул) подтверждают её
компанию — устаревший владелец после отката на старую версию доступа не даёт.

| Действие | admin | accountant | manager | user | donor |
|---|:-:|:-:|:-:|:-:|:-:|
| `GET /unified/documents`, `GET /unified/documents/{id}` | все | своя компания | своя компания (чтение) | только свои | — |
| `GET /unified/stats` | ✓ | — | — | — | — |
| `POST /unified/documents/{id}/move` | ✓ | — | — | — | — |
| `POST /unified/documents/{id}/resolve-ownership` | ✓ | — | — | — | — |
| `GET /unified/claims`, `GET /unified/documents/{id}/companies` (v1.70.85) | ✓ | — | — | — | — |
| `POST /unified/links/{id}/transfer\|decline\|void` (v1.70.85) | ✓ | — | — | — | — |
| `GET`/`PUT /unified/visibility` — показ числа организаций компаниям (v1.70.86) | ✓ | — | — | — | — |
| `GET /unified/readiness` — готовность единой записи, только числа (v1.70.88) | ✓ | — | — | — | — |
| Поле `companies_count` в `GET /receipts` и `GET /receipts/{id}` (v1.70.86) | всегда | с разрешения | с разрешения | — | — |
| Фильтр `multi_company` в `GET /receipts` (v1.70.86) | ✓ | — | — | — | — |

С 1.70.85 (ADR-20, T-34) отказ «чек у другой организации» создаёт заявку
компании; штатная роль видит только «Заявка передана администратору.» — ни
списка заявок, ни числа организаций. События решений `claim_*` в журнале
карточки и записи `unified_claim_*` в ленте событий на главной штатным ролям
не показываются.

С 1.70.86 (ADR-20, T-35) число организаций у чека видят бухгалтер и
руководитель — только если администратор разрешил показ: режим «всем
компаниям» или «выбранным компаниям» (флаг `companies.show_companies_count`)
и роль отмечена в настройке. По умолчанию показ выключен. Компания получает
только число и только по чекам своего реестра, без названий других
организаций. Сотрудник, донор Чек-Пула и платный API (B2B) поля не получают
никогда. Изменение настройки (`unified_visibility_updated`) видно только в
журнале администратора.

Конфликт принадлежности (`review_flags & REVIEW_OWNERSHIP`) скрывает документ
от компаний до разрешения администратором. Журнал `unified_events` не содержит
фискальных значений и персональных данных.

Карточка и список для штатных ролей не раскрывают другие организации (ADR-20,
T-32): чужие компании, их сотрудники и администратор платформы скрыты
(`*_hidden`), причина решения спора не отдаётся. Администратор видит всё.
