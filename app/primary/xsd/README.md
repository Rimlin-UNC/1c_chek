# Схемы ФНС для проверки электронных УПД (T-61, v1.70.95)

Здесь лежат официальные XSD-схемы формата счёта-фактуры и УПД (титул продавца). По ним
`app/primary/schema.py` проверяет загруженный XML формата 5.03. Документ считается соответствующим
формату, если его принимает хотя бы одна схема из каталога; первой проверяется самая новая редакция.

**Основание формата.** Приказ ФНС России от 19.12.2023 № ЕД-7-26/970@ в редакции приказа
№ ЕД-7-26/1032@. С 01.04.2026 операторы ЭДО принимают только 5.03 (см. `docs/primary_docs_design.md`).
В заголовке файла указан разработчик форматов ФНС (АО ГНИВЦ). Кодировка — windows-1251, как в оригинале;
байты файла не менять, иначе тест сверки хеша упадёт.

**Откуда взят файл (04.11.2026).** Сайт ФНС из рабочего окружения недоступен, поэтому файл взят с GitHub:
репозиторий `alexPisar/honest_mark_system`, путь `Reporter/XSD/ON_NSCHFDOPPR_1_997_01_05_03_05.xsd`
(скачан через API, хеш git-объекта совпал). Подлинность сверена с независимой копией — шаблоном
`ON_NSCHFDOPPR_1_997_01_05_03_01_xsd` из модуля Диадока для 1С (`soldatovde1979-ai/DIADOC-1C`):
из 262 объявлений элементов и атрибутов 247 совпали дословно. Остальные 15 — переделка под XDTO 1С:
именованные типы вместо встроенных ограничений и пространство имён, которого нет в настоящих файлах.

**Чем редакция 05 отличается от 01.** Только перечнем ставок НДС в атрибуте `НалСт`: добавлены
`18%`, `18,03%`, `22%` и `22/122`. Поэтому 05 — надмножество 01, и хранится одна она. Документ 2026 года
со ставкой 22 % редакцию 01 не проходит — это проверено тестом.

**Права.** Формат утверждён приказом ФНС, то есть является официальным документом государственного
органа. Такие документы не являются объектами авторских прав (п. 6 ст. 1259 ГК РФ).

**Новая редакция.** Положите файл `ON_NSCHFDOPPR_1_997_01_05_03_NN.xsd` рядом — он подхватится сам,
новые редакции проверяются раньше. Затем добавьте строку в таблицу выше и хеш в
`tests/test_primary_recognize.py`. Наличие более новой редакции, чем 05, на 04.11.2026 требует
уточнения на сайте ФНС.
