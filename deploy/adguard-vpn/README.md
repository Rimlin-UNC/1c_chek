# Telegram через AdGuard VPN на этом же сервере (v1.70.13)

Когда выбирать этот путь: есть лицензия AdGuard VPN и не хочется
поднимать отдельную машину для моста. Сервер считается одним устройством
лицензии; трафик Telegram-бота крошечный.

## Как это работает

    Ямастер Чек ──socks5://127.0.0.1:1080──▶ AdGuard VPN CLI
                 ──шифрованный туннель──▶ сеть AdGuard ──▶ api.telegram.org

Режим SOCKS5 у AdGuard VPN CLI поднимает только локальный прокси
(127.0.0.1:1080) — маршруты и DNS системы не меняются, остальные службы
сервера (сайт, ФНС, MAX, 1С) VPN не затрагивает. Программа «Ямастер Чек»
умеет слать трафик бота через socks5-прокси с v1.29.0 — настраивается
одним полем.

## Установка на сервере (Ubuntu)

1. **Установите CLI** (официальный установщик; на вопрос про ссылку в
   `/usr/local/bin` ответьте Y):
   ```
   curl -fsSL https://raw.githubusercontent.com/AdguardTeam/AdGuardVPNCLI/HEAD/scripts/release/install.sh | sh -s -- -v
   ```
2. **Войдите в аккаунт с лицензией** (один раз):
   ```
   adguardvpn-cli login
   ```
   CLI покажет ссылку — откройте её на любом удобном устройстве
   (компьютер/телефон) и войдите. Сервер запомнит вход.
3. **Включите режим SOCKS5** (только локальный прокси):
   ```
   adguardvpn-cli config set-mode SOCKS
   ```
   Порт по умолчанию — 1080; при желании смените:
   `adguardvpn-cli config set-socks-port 1080`.
4. **Выберите локацию**, где Telegram доступен:
   ```
   adguardvpn-cli list-locations
   ```
5. **Подключитесь и проверьте путь**:
   ```
   adguardvpn-cli connect -l "<локация из списка>"
   adguardvpn-cli status
   curl -x socks5h://127.0.0.1:1080 https://api.telegram.org/ -m 10
   ```
   Любой ответ HTTP (200/302/404) — путь жив; «таймаут» — попробуйте
   другую локацию (шаги 4–5).
6. **Автозапуск** (юнит рядом — `adguard-vpn-telegram.service`):
   ```
   sudo cp adguard-vpn-telegram.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now adguard-vpn-telegram
   ```
   ВАЖНО: вход CLI хранится в домашнем каталоге пользователя. Юнит
   запускает CLI от root — если делали `login` не под root, выполните
   один раз `sudo adguardvpn-cli login` (либо поправьте `User=`/`HOME=`
   в юните под своего пользователя).
7. **В программе**: «Настройки → Telegram» → кнопка «🛡 AdGuard VPN»
   подставит `socks5://127.0.0.1:1080` → «🔍 Диагностика» (через прокси
   должно стать ✅) → «💾 Сохранить и запустить».

## Отладка

- статус и подключение: `adguardvpn-cli status`;
- логи автозапуска: `journalctl -u adguard-vpn-telegram -f`;
- бот молчит, прокси зелёный: проверьте, что в программе указан
  `socks5://127.0.0.1:1080` и воркер запущен (строка статуса в карточке);
- сменили порт CLI: поменяйте порт и в поле «Прокси» программы.

## Безопасность

- Прокси слушает только 127.0.0.1 — снаружи недоступен (нелицевой адрес
  требует логин/пароль — см. документацию AdGuard, тут не нужно).
- Локальный участок до CLI не шифруется (это localhost), дальше трафик
  идёт в шифрованном туннеле AdGuard.
- Токен бота остаётся зашифрованным в базе программы; VPN-сервис его не
  видит — он лишь транспорт.
