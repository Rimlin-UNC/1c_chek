# AGENTS.md — вход для агентов и новых сессий

**Ямастер Чек** (`Rimlin-UNC/1c_chek`): система сканирования кассовых чеков и
интеграции с 1С:Предприятие (FastAPI). Всё о проекте — в базе знаний
[`docs/kb/README.md`](docs/kb/README.md). Начинайте с неё: там срез состояния,
задачи, решения (ADR), runbook, состояние БД, открытые вопросы и журнал сессий.

## Порядок работы

Пошагово — [`docs/kb/07_agent_algorithm.md`](docs/kb/07_agent_algorithm.md):
старт сессии и сверка с фактом → задача из
[`02_roadmap.csv`](docs/kb/02_roadmap.csv) → ветка сессии → тест, потом код →
проверки → PR → база знаний в том же PR → деплой → отчёт владельцу на русском.

## Проверки

| Что | Команда |
|---|---|
| Окружение | `qa/setup_dev.sh --with-postgres` |
| Критичный набор | `./test.sh` |
| Полный прогон | `./test.sh full -j2` |
| Линтеры | `.venv/bin/ruff check app tests qa` · `npm run lint` |
| CI | [`.github/workflows/ci.yml`](.github/workflows/ci.yml): Python 3.11 и 3.12, PostgreSQL 17, вся цепочка; ворота — 0 упавших и 0 пропущенных тестов |

Выпуск версии — по [`docs/update_playbook.md`](docs/update_playbook.md) и
разделу «Стандарт выпуска» в [runbook](docs/kb/04_runbook.md).

## Только после явного «да» владельца

Слияние в `main`; любые изменения в Supabase (DDL, данные, права, история
миграций, удаление `qa_lock_…`); настройки и production-деплой Vercel;
действия на рабочем сервере и перенос архива; блок ФНС, пауза антибана и
квота. Полный стоп-лист — в алгоритме.

## Никогда

- Секреты в репозитории, базе знаний, issues и PR: только имена переменных и
  их назначение.
- Строки рабочих данных и персональные данные: только схема и агрегаты.
- Выдумывать: нет данных или они противоречат друг другу — «требует уточнения».
