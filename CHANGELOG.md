## [1.6.0] — 2026-10-03 — «Обновления без промахов и лёгкий клиент»

### 🔄 Обновления: надёжно даже при блокировках
- **Проверка версии по трём независимым каналам GitHub**: api.github.com → raw.githubusercontent.com → git-протокол (порт 443). Причина молчания в 1.4.0: провайдеры РФ периодически блокируют raw.githubusercontent.com, а проверка ходила только туда.
- Сравнение версий «только вперёд» (числовой семвер): случайное понижение версии не предлагается как обновление.
- При недоступности GitHub проверка отдаёт понятную причину (200 + ok:false) вместо пустой ошибки; в карточке — красный статус, текст ошибки и **готовая команда ручного обновления** (`sudo bash deploy.sh --update`).
- Новый раздел «Источник обновлений»: репозиторий (owner/repo) и ветка видны и меняются прямо в карточке (PUT /api/v1/admin/update/repo), с валидацией.

### 🪶 Лёгкий клиент: меньше нагрузки на сервер
- **GZip-сжатие** ответов API и статики — трафик между браузером и сервером кратно меньше.
- **HTTP-кэш**: статика (js/css/иконки) кэшируется браузером на 7 дней; sw.js и оболочка приложения — всегда свежие (no-cache).
- **Скрытая вкладка — тишина**: WebSocket-пульс не отправляется в фоне; WS-события сливаются в одну перерисовку (debounce 1.2 с) — при пачке чеков один запрос вместо десятков.

### 🎨 Визуализация
- Карточка «Обновления»: статус-индикатор (зелёный — последняя версия / пульсирующий — проверка / оранжевый — доступна новая / красный — нет связи), подсказка канала проверки.
- Дашборд: тренд «неделя к неделе» (▲/▼ %) в карточке «Чеков в системе».
- WHATS_NEW 1.6.0.

### 🛠 Деплой: домен и SSL больше не теряются при обновлении
- **Параметры запоминаются**: домен, SSL и ветка сохраняются в `/etc/ymaster-check/deploy.conf` и автоматически применяются при следующем `--update` (раньше повторный запуск без аргументов возвращал голый HTTP-шаблон и сайт оставался только по http://IP).
- **HTTPS восстанавливается сам**: если сертификат Let's Encrypt уже выпущен, deploy.sh находит его и заново собирает 443-блок Nginx (сертификат + http→https редирект).
- Автопоиск домена по выпущенным сертификатам; флаг `--no-ssl` — осознанно отключить HTTPS.
- Исправлен вывод: «Веб-клиент: http://IP (или http://IP)» → теперь адрес с доменом либо чистый IP без дублирования.
- Технически: вставка ssl-строк через awk (многострочный `sed a\` внутри кавычек ломался bash-склейкой `\`+перевод строки).

### Прочее
- /system отдаёт repo_url/branch; версии 1.6.0 (config/sw/manifest).
- Тесты: +12 (семвер, фолбэки каналов, ok:false, PUT /update/repo, кэш-заголовки, gzip).

## [1.5.0] — 2026-10-02 — «Установка на устройство и надёжность данных»

### Установка приложения (PWA)
- **Кнопка «📲 Установить приложение»** в меню (и в Настройках) для ВСЕХ ролей: Android/Windows/macOS — установка в один клик (beforeinstallprompt); iPhone/iPad — пошаговая инструкция «Поделиться → На экран "Домой"».

### Надёжность данных: резервные копии (админ)
- Новый сервис `app/services/backups.py` — многоуровневые автокопии БД: **ежедневные** (хранятся 7), **перед каждым обновлением** (5), **вручную** (10), **архив месяца** (12 месяцев, идемпотентно).
- Ежедневная копия создаётся автоматически фоновым демоном при первом запуске/смене суток.
- API админа: список копий, создание, скачивание (`/api/v1/admin/backups*`), защита от path traversal.
- Карточка «💾 Резервные копии» в Настройках: создать копию, список с типом/размером, скачивание.
- Обновление из приложения дополнительно делает копию уровня preupdate — **данные и БД не затираются никогда**.

### Вёрстка
- Страница «Маппинг»: правила — аккуратные карточки-строки с подписями полей, счётчик «правил: N · с реквизитом: M», корректный адаптив (980px → 2 колонки, 560px → стек).

### Прочее
- `data/` полностью исключён из git (случайно попавшие бэкапы удалены из репозитория) — данные на сервере не трогаются ни обновлениями, ни git.
- Тесты: +11 (бэкапы, PWA-инфраструктура, разметка маппинга) — всего **79 passed**.

## [1.2.0] — 2026-10-01 — Данные чека из сервисов · редактирование · стабильная связь

### Добавлено
- **Получение полных данных чека из внешних источников** (v1.2.0):
  официальное API ФНС, proverkacheka.com (`POST /api/v1/check/get`, qrraw+token),
  свой источник по контракту `POST {qrraw} → JSON` (готов к проверкачека.рф).
  В чек вносятся: магазин, ИНН, адрес, кассир, наличные/безнал и **все позиции**.
- **Антибан-механика**: последовательная очередь запросов, случайная пауза
  2–7 секунд перед каждым обращением, ротация источников, «остывание» источника
  при 429/403 (10 мин → 6 ч), кэш проверок 7 дней.
- **Редактирование чеков**: бухгалтер/админ могут изменить любые поля чека
  (дата, сумма, тип, ФН/ФД/ФП, магазин, сотрудник) и позиции — по одному
  чеку или массово; изменение ФН/ФД/ФП защищено проверкой уникальности;
  реквизиты уже выгруженных в 1С чеков правит только администратор.
- **«От кого прислал»**: чеки от сотрудников автоматически помечаются
  отправителем; изменять привязку могут только бухгалтер/администратор.
- **Уведомления сотрудников**: флажок 🔔 «Требует внимания бухгалтерии»
  и комментарий к своему чеку (замена, возврат и т.п.).
- **Форма API ФНС**: ввод Мастер-токена прямо в настройках (Настройки →
  «Проверка чеков»), без правки .env; тест источника контрольным чеком.
- Кнопки: 📥 «Данные сервисов» (один чек / выбранные), ✏️ редактор чека
  с таблицей позиций, «🧪 Тест контрольным чеком».
- CSV: новые колонки «Магазин», «ИНН», «Уведомление»; Push-выгрузка в 1С:
  новые поля merchant/merchant_inn/merchant_address/notified.
- Раздел «Что нового» в приложении — показывается один раз на версию.

### Исправлено
- **«Офлайн» и мерцание на телефоне**: у WS-статуса было два обработчика
  onopen (второй затирал первый — индикатор никогда не показывал «онлайн»);
  добавлены heartbeat клиента/сервера (25/20 с), растущая пауза переподключения
  2→60 с с разбросом, гистерезис индикатора, пауза попыток в фоне
  (document.hidden), мгновенное одно переподключение при возврате в приложение.

### Безопасность
- PATCH чека: сотрудник может менять только notified/comment своего чека
  (проверено тестами); чужой чек сотруднику недоступен.

### Тесты
- 44 passed (было 31): +13 по источникам, парсеру сумм (копейки/рубли),
  ротации при 429, правам PATCH, авто-привязке отправителя.

## [1.1.0] — 2026-09-22

### Добавлено
- **Ролевая модель v2:** Администратор (всегда один, все права) / Бухгалтер
  (расширенные: проверка ФНС, выгрузка, назначение сотрудника) / Пользователь
  (сканирование, только свои чеки). Проверка прав дублируется на сервере и клиенте.
- **Регистрация только по приглашениям:** администратор создаёт ссылку с ролью
  (одноразовую/многоразовую, со сроком); регистратор сразу получает роль. Роль
  «администратор» через приглашение недоступна.
- **Один администратор:** создание второго админа запрещено (валидация + обработчик);
  передача прав `POST /users/{id}/promote-admin` (целевой — админ, прежний — бухгалтер).
- **Обязательная смена временного пароля** (`must_change_password`): первый вход
  администратора и сброс пароля требуют задать новый (несбрасываемое окно).
- **Безопасность:** rate limiting (скользящее окно: login 10/мин, регистрация 20/час,
  API 240/мин → 429 + Retry-After); LoginGuard (5 неудачных входов → блок 15 мин);
  security headers (CSP, X-Frame-Options, nosniff, Referrer/Permissions-Policy).
- **Анти-DoS на периметре:** Nginx limit_req/limit_conn, UFW (только 22/80/443 наружу),
  fail2ban (бан IP за перебор по access-логу) — конфиги в deploy/, ставит deploy.sh.
- **deploy.sh:** развёртывание на Ubuntu 24.04 прямо из GitHub-ветки одной командой,
  режим `--update`, поддержка приватного репозитория через GITHUB_TOKEN, Nginx+UFW+fail2ban.
- **Автоматизация рутины бухгалтера (по анализу рынка Entera/1С:Распознавание):**
  - поле «Сотрудник (подотчётник)» на чеке: массовое назначение, подсказки, попадание
    в EnterpriseData (Контрагент) и Push-payload;
  - авто-проверка чека в ФНС сразу после сканирования (настройка, по умолчанию вкл.);
  - CSV-экспорт для Excel (разделитель «;», BOM, суммы с запятой).
- Комментарий к чеку; поиск по сотруднику; фильтр по сотруднику.

### Изменено
- `GET /settings/mapping` и лента дашборда — бухгалтер+; журнал — только админ;
- список чеков: пользователь видит только свои (серверный фильтр);
- SW-кэш v2 (обновление статики у клиентов).
